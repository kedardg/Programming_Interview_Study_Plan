3-Month Schedule

For 1 hour each weekday and 4 hours each weekend day: about 169 hours over 13 weeks, set up for an RTX 5080. It covers the core of each track and keeps the rest of the plan as reference. Every week touches every track, and no weekday repeats the day before it. In the table, # numbers are Blind 75 problems (Step 4), L numbers are GPU MODE lectures and Ch numbers are system design chapters (Step 21).

Rules

  • Swap freely: any cell can trade places with a later week, except in the kernels column, which builds on itself.
  • Stuck on LeetCode: keep the 45-minute cap, then watch the matching tutorial on Aditya Verma's channel before you re-try. Stuck on a kernel for more than 30 minutes: skip to the next part, ask on the GPU MODE Discord, and come back next Saturday.
  • Premium problems (#32#33#34, #38#39, #59) are optional. Do them in re-solve time if you have LeetCode Premium.
  • Left for after the 3 months: most lectures and readings in Steps 13-17, the other Vol 2 system design chapters, and the 100 / 50 / 2 LeetCode target.

RTX 5080 Notes

  • Use Linux, or WSL2 on Windows. Triton and vLLM don't officially support native Windows.
  • Install a recent NVIDIA driver, the CUDA Toolkit 12.8 or newer, and PyTorch 2.7 or newer built for CUDA 12.8. Older builds fail with "no kernel image" errors.
  • Let Nsight Compute read the GPU performance counters: on Linux, run it with sudo or set NVreg_RestrictProfilingToAdminUsers=0; on Windows, allow access in the NVIDIA Control Panel.
  • The 5080 is consumer Blackwell (sm_120). Its tensor cores use warp-level mma.sync, extended to FP8, FP6 and FP4. Hopper's wgmma and datacenter Blackwell's tcgen05 and tensor memory don't run on it, so read that material as theory.
  • It has 16 GB of memory: serve small models, or 4-bit 7-8B models.
  • Multi-GPU code (NCCL, Step 15) needs 2 or more GPUs. Read it, or rent a multi-GPU machine for an hour.

How to Study Each Lecture

  1. Read the matching PMPP chapter (if there is one)
  2. Watch the lecture
  3. Open the slides/notebook and re-run the code yourself
  4. Rewrite the kernel from scratch without looking
  5. Check it against the PyTorch version for correctness
  6. Profile it and benchmark it against PyTorch
  7. Try one optimization and measure again
  8. Explain what you learned in English (notes, blog post, or README)

Read - KV cache systems

First be able to size a cache by hand: KV bytes = 2 × layers × KV heads × head dim × cached tokens × batch × bytes per element. MHA, GQA, MQA, and MLA differ only in how many KV heads (or latent dimensions) survive that formula, which is why the attention variant decides how many concurrent users fit on a GPU.

  • Understanding KV Cache - Why decode caches keys and values, the sizing formula, and a worked 70B MHA example that reaches about 1.25 TiB of cache for 16 users at 32K tokens, against about 140 GB for the BF16 weights.
  • KV Cache Calculator - Check your hand-computed numbers, then vary the model, attention variant, precision, batch size, and context length until the trade-offs are intuitive.
  • Grouped-Query Attention - Fewer key-value heads and a smaller KV cache.
  • DeepSeek-V2 - Multi-head latent attention and compressed KV state.
  • KIVI - KV quantization with separate treatment for keys and values.
  • CacheGen - KV compression for transfer.
  • Mooncake - A distributed KV cache and data plane.

Read - Speculative decoding

  • Fast Inference from Transformers via Speculative Decoding - Exact sampling with a draft model.
  • Accelerating Large Language Model Decoding with Speculative Sampling - The parallel formulation and analysis.

Read - Structured decoding and fairness

  • Guiding LLMs the Right Way - Constrained decoding without changing the intended token distribution.

Read - Fine-tuning and post-training stacks

Its feature list - sample packing, FlashAttention, Liger kernels, FSDP2, tensor and sequence/context parallelism, QLoRA, FP8, and MoE expert parallelism - is a map of how the kernel and parallelism ideas from Steps 10-15 are applied on the training side.
  • LoRA - Low-rank adapters instead of updating all weights.
  • QLoRA - Adapters trained over a 4-bit quantized base model.
  • DPO - Preference tuning without a separate reward model.
  • Try it: QLoRA fine-tune a 4-bit 7-8B model on your 5080 from one of Axolotl's example configs (axolotl fetch examples), then serve the merged checkpoint with vLLM and measure TTFT and TPOT.
