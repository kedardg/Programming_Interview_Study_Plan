ML Coding from Scratch: CS336 Assignment 1 as Muscle Memory

The most common technical interview for research-engineer and MTS roles is not LeetCode and not a whiteboard discussion: it is "open a blank file and implement this piece of a transformer, then debug it with me." This chapter turns Stanford CS336's Assignment 1 — the exact set of functions Alisa Liu called crucial to drill until automatic — into an interview-speed build, with the shape contracts, the classic bugs, and the tests that catch them.

1. Why this interview dominates, and how it is graded

Two first-hand accounts in the job-prep collection agree on the same thing from different angles. Alisa Liu, after 57 interviews across 11 companies, reports that ML coding was by far the most common interview type, that CS336's assignment 1 was "crucial," and that she practiced with AI assistance completely off to mimic interview conditions — because you underestimate how much you lean on it otherwise. Nathan Lambert's account of his own job hunt describes the same pattern from the other side of the table: the interviewer wants to watch you implement something you have implemented before, so that the signal is fluency and debugging, not whether you happen to know the formula.

What is actually being graded, in rough order of weight:

  1. Correctness with shapes. You should be able to say the shape of every tensor before you create it: (B, T, d_model) in, (B, h, T, d_k) after the head split, (B, h, T, T) for scores. Interviewers listen for this narration.
  2. Debugging fluency. Something will break (often they break it on purpose). Can you bisect with a tiny input, print shapes, and name the bug in under two minutes?
  3. Explaining as you go. Why pre-norm, why the 1/√d_k, why upcast RMSNorm to float32, why AdamW decouples weight decay. One sentence each, while typing.
  4. Judgment under time. Knowing which corners are safe to cut in 45 minutes (no KV cache, no dropout) and which are not (the causal mask, numerical stability).

The practice protocol

  • Timer at 45 minutes. Blank file. No autocomplete, no chat assistant, no copying from a previous attempt.
  • Implement one target (say, multi-head attention with RoPE) against the assignment's tests: uv run pytest tests/test_model.py -k rope.
  • When a test fails, resist reading the reference. Print shapes, build a 2-token example by hand, find it.
  • Repeat the same target on three separate days before moving on. "Muscle memory" means the third attempt takes a third of the time of the first.
  • Finish every session by explaining one component aloud in 60 seconds, as if to an interviewer.

2. The build, in the assignment's order

CS336 A1 wires your code to its tests through tests/adapters.py: each run_* function receives the reference weights and inputs and must return exactly what the reference does, so every component below has a test that tells you whether you are right. The order here is the order of the adapters, which is also a sensible order to write them in an interview: leaves first, then the block, then the model, then training.

2.1 Linear — test_linear

No bias (modern LLMs drop them), weight stored as (d_out, d_in) so the forward is x @ W.T. Initialize with a truncated normal of standard deviation sqrt(2/(d_in+d_out)), truncated at ±3σ; the test loads reference weights, but an interviewer will ask how you initialize.

import math, torch, torch.nn as nn
from einops import einsum  # optional; the plain @ is fine in an interview

class Linear(nn.Module):
    def __init__(self, d_in, d_out, device=None, dtype=None):
        super().__init__()
        self.weight = nn.Parameter(torch.empty(d_out, d_in, device=device, dtype=dtype))  # (d_out, d_in)
        std = math.sqrt(2.0 / (d_in + d_out))
        nn.init.trunc_normal_(self.weight, mean=0.0, std=std, a=-3*std, b=3*std)

    def forward(self, x):                 # x: (..., d_in)
        return x @ self.weight.T          # (..., d_out)

Classic bug: storing the weight as (d_in, d_out) and forgetting the transpose when the test hands you a (d_out, d_in) tensor — the matmul still runs when d_in == d_out and silently produces garbage. Always write the shape in the comment.

2.2 Embedding — test_embedding

class Embedding(nn.Module):
    def __init__(self, vocab_size, d_model, device=None, dtype=None):
        super().__init__()
        self.weight = nn.Parameter(torch.empty(vocab_size, d_model, device=device, dtype=dtype))
        nn.init.trunc_normal_(self.weight, std=1.0, a=-3.0, b=3.0)

    def forward(self, token_ids):         # token_ids: (...) int64
        return self.weight[token_ids]     # (..., d_model) — advanced indexing is the whole layer

2.3 RMSNorm — test_rmsnorm

Normalize by the root-mean-square over the last dimension, then scale by a learned gain. Upcast to float32 before squaring: in bf16 the sum of squares of a 4096-wide vector loses precision badly, and the reference does the upcast too. No mean subtraction, no bias — that is the entire difference from LayerNorm.

class RMSNorm(nn.Module):
    def __init__(self, d_model, eps=1e-5, device=None, dtype=None):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(d_model, device=device, dtype=dtype))

    def forward(self, x):                 # x: (..., d_model)
        in_dtype = x.dtype
        x = x.to(torch.float32)
        rms = torch.sqrt(x.pow(2).mean(dim=-1, keepdim=True) + self.eps)   # (..., 1)
        return (x / rms * self.weight).to(in_dtype)

2.4 SiLU and the SwiGLU FFN — test_silu_matches_pytorch, test_swiglu

SiLU is x·σ(x). SwiGLU gates one up-projection with the SiLU of another, then projects down: W2 (SiLU(W1 x) ⊙ W3 x). With three matrices instead of two, d_ff is set to about 8/3·d_model, rounded to a multiple of 64 for tensor-core efficiency, so parameter count matches a classic 4× FFN.

def silu(x):
    return x * torch.sigmoid(x)

class SwiGLU(nn.Module):
    def __init__(self, d_model, d_ff=None, device=None, dtype=None):
        super().__init__()
        if d_ff is None:
            d_ff = 64 * round(8 * d_model / 3 / 64)          # ≈ 8/3·d_model, multiple of 64
        self.w1 = Linear(d_model, d_ff, device, dtype)        # (d_ff, d_model)
        self.w3 = Linear(d_model, d_ff, device, dtype)        # (d_ff, d_model)
        self.w2 = Linear(d_ff, d_model, device, dtype)        # (d_model, d_ff)

    def forward(self, x):                                     # (..., d_model)
        return self.w2(silu(self.w1(x)) * self.w3(x))         # (..., d_model)

Classic bug: swapping which projection gets the SiLU. The test's reference weights make w1 the gated branch; if you SiLU w3 instead, every number is wrong but the shapes are right.

2.5 RoPE — test_rope

Rotary position embedding rotates each consecutive pair of dimensions (2i, 2i+1) of a query or key by an angle pos · θ^(−2i/d_k). Precompute the cos and sin tables once for max_seq_len positions and index them by token_positions; apply to Q and K only, per head, after the head split, before the dot product. The dot product of two rotated vectors then depends only on their relative offset — see the Attention chapter for why.

class RotaryPositionalEmbedding(nn.Module):
    def __init__(self, theta, d_k, max_seq_len, device=None):
        super().__init__()
        inv_freq = theta ** (-torch.arange(0, d_k, 2, device=device).float() / d_k)   # (d_k/2,)
        pos = torch.arange(max_seq_len, device=device).float()                        # (L,)
        angles = torch.outer(pos, inv_freq)                                           # (L, d_k/2)
        self.register_buffer("cos", angles.cos(), persistent=False)
        self.register_buffer("sin", angles.sin(), persistent=False)

    def forward(self, x, token_positions):      # x: (..., T, d_k); positions: (..., T)
        cos = self.cos[token_positions]         # (..., T, d_k/2)
        sin = self.sin[token_positions]
        x1, x2 = x[..., 0::2], x[..., 1::2]     # even / odd dims, each (..., T, d_k/2)
        out = torch.empty_like(x)
        out[..., 0::2] = x1 * cos - x2 * sin
        out[..., 1::2] = x1 * sin + x2 * cos
        return out

Classic bugs: pairing the first half with the second half (the "rotate_half" convention of some codebases) when the reference pairs adjacent dims — both are valid RoPEs, but only one matches the snapshot; and applying RoPE to V, which has no positional meaning and ruins the model. When token_positions is None, use arange(T).

2.6 Softmax — test_softmax_matches_pytorch

def softmax(x, dim):
    x = x - x.amax(dim=dim, keepdim=True)        # subtract the max: exp cannot overflow now
    e = torch.exp(x)
    return e / e.sum(dim=dim, keepdim=True)

The max-subtraction is the one trick that must be automatic: exp(1000) is inf in every float type, and softmax is shift-invariant so the answer is unchanged. The kernels chapter turns this into the online softmax behind FlashAttention.

2.7 Scaled dot-product attention — test_scaled_dot_product_attention, test_4d_scaled_dot_product_attention

The mask is boolean, True where attention is allowed. Fill the disallowed positions with -inf before softmax so they get exactly zero weight. Scale by 1/√d_k so the logits do not grow with dimension and saturate the softmax.

def scaled_dot_product_attention(Q, K, V, mask=None):
    # Q: (..., Tq, d_k)  K: (..., Tk, d_k)  V: (..., Tk, d_v)  mask: (..., Tq, Tk) bool, True = keep
    d_k = Q.shape[-1]
    scores = Q @ K.transpose(-2, -1) / math.sqrt(d_k)       # (..., Tq, Tk)
    if mask is not None:
        scores = scores.masked_fill(~mask, float("-inf"))
    weights = softmax(scores, dim=-1)                       # rows sum to 1
    return weights @ V                                      # (..., Tq, d_v)

The 4-D test passes (B, h, T, d) tensors: writing everything in terms of the last two dims makes batch and head dims fall through for free.

2.8 Causal multi-head self-attention — test_multihead_self_attention, …_with_rope

Project to Q, K, V with one (d_model, d_model) matrix each (the reference stores all heads concatenated along rows, head 0 first), split into heads, apply RoPE to Q and K per head, build the causal mask with tril, attend, merge heads, project out.

class CausalMultiHeadSelfAttention(nn.Module):
    def __init__(self, d_model, num_heads, max_seq_len=None, theta=None, device=None, dtype=None):
        super().__init__()
        assert d_model % num_heads == 0
        self.h, self.d_k = num_heads, d_model // num_heads
        self.q_proj = Linear(d_model, d_model, device, dtype)   # weight (h*d_k, d_model), head-major rows
        self.k_proj = Linear(d_model, d_model, device, dtype)
        self.v_proj = Linear(d_model, d_model, device, dtype)
        self.output_proj = Linear(d_model, d_model, device, dtype)
        self.rope = RotaryPositionalEmbedding(theta, self.d_k, max_seq_len, device) if theta else None

    def forward(self, x, token_positions=None):             # x: (B, T, d_model)
        B, T, _ = x.shape
        def split(t):                                       # (B, T, h*d_k) -> (B, h, T, d_k)
            return t.view(B, T, self.h, self.d_k).transpose(1, 2)
        q, k, v = split(self.q_proj(x)), split(self.k_proj(x)), split(self.v_proj(x))
        if self.rope is not None:
            if token_positions is None:
                token_positions = torch.arange(T, device=x.device)
            q = self.rope(q, token_positions)               # positions broadcast over (B, h)
            k = self.rope(k, token_positions)
        mask = torch.tril(torch.ones(T, T, dtype=torch.bool, device=x.device))   # (T, T) True below diagonal
        out = scaled_dot_product_attention(q, k, v, mask)   # (B, h, T, d_k)
        out = out.transpose(1, 2).contiguous().view(B, T, self.h * self.d_k)     # merge heads
        return self.output_proj(out)                        # (B, T, d_model)

Classic bugs: view after transpose without contiguous() (RuntimeError, or worse, a reshape that scrambles heads); splitting heads as view(B, h, T, d_k) directly — which interleaves tokens and heads — instead of view(B, T, h, d_k).transpose(1, 2); and applying RoPE before the head split, which rotates pairs that straddle head boundaries.

2.9 The pre-norm transformer block — test_transformer_block

class TransformerBlock(nn.Module):
    def __init__(self, d_model, num_heads, d_ff, max_seq_len, theta, device=None, dtype=None):
        super().__init__()
        self.ln1 = RMSNorm(d_model, device=device, dtype=dtype)
        self.attn = CausalMultiHeadSelfAttention(d_model, num_heads, max_seq_len, theta, device, dtype)
        self.ln2 = RMSNorm(d_model, device=device, dtype=dtype)
        self.ffn = SwiGLU(d_model, d_ff, device, dtype)

    def forward(self, x, token_positions=None):             # (B, T, d_model)
        x = x + self.attn(self.ln1(x), token_positions)     # pre-norm: normalize the input to the sublayer,
        x = x + self.ffn(self.ln2(x))                       # add the sublayer output to the untouched stream
        return x

State-dict keys matter for the test: attn.q_proj.weight, attn.output_proj.weight, ln1.weight, ffn.w1.weight… Name your submodules to match and load_state_dict does the rest.

2.10 The transformer LM — test_transformer_lm, test_transformer_lm_truncated_input

class TransformerLM(nn.Module):
    def __init__(self, vocab_size, context_length, d_model, num_layers, num_heads, d_ff, rope_theta,
                 device=None, dtype=None):
        super().__init__()
        self.context_length = context_length
        self.token_embeddings = Embedding(vocab_size, d_model, device, dtype)
        self.layers = nn.ModuleList([
            TransformerBlock(d_model, num_heads, d_ff, context_length, rope_theta, device, dtype)
            for _ in range(num_layers)])
        self.ln_final = RMSNorm(d_model, device=device, dtype=dtype)
        self.lm_head = Linear(d_model, vocab_size, device, dtype)      # untied: separate (vocab, d_model)

    def forward(self, in_indices):                                       # (B, T) int
        B, T = in_indices.shape
        assert T <= self.context_length
        x = self.token_embeddings(in_indices)                            # (B, T, d_model)
        pos = torch.arange(T, device=in_indices.device)
        for layer in self.layers:
            x = layer(x, pos)
        return self.lm_head(self.ln_final(x))                            # (B, T, vocab) logits, no softmax

The truncated-input test checks that a shorter sequence gives the same logits for the shared prefix — which is exactly what causal masking plus position-indexed RoPE guarantees, and exactly what breaks if you ever let position t see position t+1. Return logits, not probabilities: the loss takes logits.

Tied vs untied embeddings: GPT-2 tied lm_head to the input embedding (saves vocab×d_model parameters); the CS336 reference and Llama keep them separate. Say which you are doing.

2.11 Cross-entropy — test_cross_entropy

def cross_entropy(logits, targets):
    # logits: (B, V)  targets: (B,) int64 — returns the mean negative log-likelihood
    logits = logits - logits.amax(dim=-1, keepdim=True)          # stabilize: shift-invariant
    log_probs = logits - torch.log(torch.exp(logits).sum(dim=-1, keepdim=True))   # log-softmax
    nll = -log_probs.gather(dim=-1, index=targets.unsqueeze(-1)).squeeze(-1)      # (B,)
    return nll.mean()

Never compute log(softmax(x)) as two steps — the probabilities underflow to zero and the log is −inf. Log-sum-exp in one expression is the interview answer. For a (B, T, V) logit tensor, flatten to (B·T, V) first.

2.12 AdamW — test_adamw

Adam keeps per-parameter first (m) and second (v) moment estimates; the bias correction divides by 1−β^t so early steps are not shrunk by the zero initialization. AdamW's one change: weight decay is applied directly to the weights, not added to the gradient, so it is not rescaled by the adaptive denominator.

class AdamW(torch.optim.Optimizer):
    def __init__(self, params, lr=1e-3, betas=(0.9, 0.999), eps=1e-8, weight_decay=0.01):
        super().__init__(params, dict(lr=lr, betas=betas, eps=eps, weight_decay=weight_decay))

    @torch.no_grad()
    def step(self, closure=None):
        loss = None if closure is None else closure()
        for group in self.param_groups:
            lr, (b1, b2), eps, wd = group["lr"], group["betas"], group["eps"], group["weight_decay"]
            for p in group["params"]:
                if p.grad is None:
                    continue
                state = self.state[p]
                if not state:                                   # lazy init
                    state["t"] = 0
                    state["m"] = torch.zeros_like(p)
                    state["v"] = torch.zeros_like(p)
                state["t"] += 1
                t, m, v, g = state["t"], state["m"], state["v"], p.grad
                m.mul_(b1).add_(g, alpha=1 - b1)                # m = β1 m + (1-β1) g
                v.mul_(b2).addcmul_(g, g, value=1 - b2)         # v = β2 v + (1-β2) g²
                lr_t = lr * math.sqrt(1 - b2 ** t) / (1 - b1 ** t)   # bias correction folded into lr
                p.addcdiv_(m, v.sqrt().add_(eps), value=-lr_t)  # p -= lr_t · m / (√v + ε)
                p.mul_(1 - lr * wd)                             # decoupled weight decay (uses lr, not lr_t)
        return loss

Classic bugs: using lr_t for the decay term (the reference uses plain lr), adding eps before the square root, and applying weight decay to RMSNorm gains or biases in a real training run (fine for the test, bad for the model — use parameter groups).

SGD (grey) steps by lr·g, so its step size collapses in flat regions and jumps in steep ones; AdamW (blue) divides by √v̂, so its early steps are roughly lr in size regardless of gradient scale — watch the m̂, v̂ readouts. Push β1 up and it coasts through the ripples; add weight decay and it settles short of the minimum, pulled toward zero.

2.13 Cosine schedule with warmup — test_get_lr_cosine_schedule

def get_lr_cosine_schedule(it, max_lr, min_lr, warmup_iters, cosine_cycle_iters):
    if it < warmup_iters:                                   # linear warmup from 0
        return max_lr * it / warmup_iters
    if it > cosine_cycle_iters:                             # after the cycle: floor
        return min_lr
    progress = (it - warmup_iters) / (cosine_cycle_iters - warmup_iters)
    return min_lr + 0.5 * (1 + math.cos(math.pi * progress)) * (max_lr - min_lr)

The test uses warmup_iters=7, cosine_cycle_iters=21, min_lr = 0.1·max_lr; the off-by-one that bites is treating the boundary iteration as warmup instead of the start of the cosine.

Interactive: the schedule

Warmup protects the early steps while Adam's moment estimates are still noisy; the cosine decays smoothly to the floor and stays there. Real runs use thousands of warmup steps and a cycle equal to the training horizon.

2.14 Gradient clipping — test_gradient_clipping

def gradient_clipping(parameters, max_l2_norm, eps=1e-6):
    grads = [p.grad for p in parameters if p.grad is not None]
    total = torch.sqrt(sum((g.float() ** 2).sum() for g in grads))     # global L2 norm over ALL params
    if total > max_l2_norm:
        scale = max_l2_norm / (total + eps)
        for g in grads:
            g.mul_(scale)                                                 # in place

Clip the global norm, not per-parameter norms; a single bad batch produces a few enormous gradients and this bounds the step they can cause.

2.15 Data loading — test_get_batch

import numpy as np
def get_batch(dataset, batch_size, context_length, device):
    # dataset: 1-D int array (use np.memmap for files bigger than RAM)
    starts = np.random.randint(0, len(dataset) - context_length, size=batch_size)      # valid offsets
    x = np.stack([dataset[s : s + context_length] for s in starts])                      # (B, T)
    y = np.stack([dataset[s + 1 : s + context_length + 1] for s in starts])              # shifted by one
    return (torch.from_numpy(x.astype(np.int64)).to(device),
            torch.from_numpy(y.astype(np.int64)).to(device))

Labels are the inputs shifted by one — the whole language-modeling objective is in that +1. The upper bound of the random offset must leave room for the shifted label (len − context_length, exclusive).

2.17 BPE: training and the tokenizer — test_train_bpe*, test_tokenizer.py

Byte-pair encoding starts from the 256 byte values and repeatedly merges the most frequent adjacent pair. Two details make the assignment's version match GPT-2's: (1) pre-tokenization — split the text with GPT-2's regex so merges never cross word or punctuation boundaries, and count each pre-token once with its frequency instead of scanning the corpus per merge; (2) special tokens — split the text on them first so <|endoftext|> is never merged with its neighbors and gets its own id. Ties in pair frequency are broken by the lexicographically greater pair.

import regex as re
from collections import Counter, defaultdict
PAT = r"""'(?:[sdmt]|ll|ve|re)| ?\p{L}+| ?\p{N}+| ?[^\s\p{L}\p{N}]+|\s+(?!\S)|\s+"""   # GPT-2 pre-tokenizer

def train_bpe(input_path, vocab_size, special_tokens):
    text = open(input_path, encoding="utf-8").read()
    vocab = {i: bytes([i]) for i in range(256)}
    for tok in special_tokens:
        vocab[len(vocab)] = tok.encode("utf-8")
    # 1. pre-tokenize, counting each distinct pre-token once; never cross special tokens
    chunks = re.split("|".join(re.escape(t) for t in special_tokens), text) if special_tokens else [text]
    counts = Counter()
    for chunk in chunks:
        for m in re.finditer(PAT, chunk):
            counts[tuple(bytes([b]) for b in m.group().encode("utf-8"))] += 1   # word as tuple of byte-tokens
    merges = []
    # 2. merge loop
    while len(vocab) < vocab_size:
        pair_counts = defaultdict(int)
        for word, c in counts.items():
            for a, b in zip(word, word[1:]):
                pair_counts[(a, b)] += c
        if not pair_counts:
            break
        best = max(pair_counts, key=lambda p: (pair_counts[p], p))      # ties: lexicographically greater
        merges.append(best)
        vocab[len(vocab)] = best[0] + best[1]
        new_counts = Counter()
        for word, c in counts.items():                                   # apply the merge to every word
            out, i = [], 0
            while i < len(word):
                if i < len(word) - 1 and (word[i], word[i + 1]) == best:
                    out.append(best[0] + best[1]); i += 2
                else:
                    out.append(word[i]); i += 1
            new_counts[tuple(out)] += c
        counts = new_counts
    return vocab, merges

That loop recounts every pair each iteration, which is O(merges × corpus) and fails test_train_bpe_speed (1.5 s on the small corpus) at scale; the production fix is to keep pair counts incrementally — only words containing the merged pair change — and to pre-tokenize in parallel chunks split at a special-token boundary (the assignment's find_chunk_boundaries helper). In an interview, write the simple version first and say exactly which line you would optimize.

class Tokenizer:
    def __init__(self, vocab, merges, special_tokens=None):
        self.vocab, self.inv = vocab, {b: i for i, b in vocab.items()}
        self.rank = {pair: i for i, pair in enumerate(merges)}        # earlier merge = lower rank = applied first
        self.special = sorted(special_tokens or [], key=len, reverse=True)   # longest first: overlapping specials
        for s in self.special:
            if s.encode() not in self.inv:
                self.vocab[len(self.vocab)] = s.encode(); self.inv[s.encode()] = len(self.vocab) - 1

    def _bpe(self, word):                       # word: list of byte-tokens
        while len(word) > 1:
            pairs = [(self.rank.get((a, b), float("inf")), i) for i, (a, b) in enumerate(zip(word, word[1:]))]
            r, i = min(pairs)
            if r == float("inf"):
                break
            word = word[:i] + [word[i] + word[i + 1]] + word[i + 2:]
        return word

    def encode(self, text):
        ids = []
        parts = re.split("(" + "|".join(re.escape(s) for s in self.special) + ")", text) if self.special else [text]
        for part in parts:
            if part in self.special:
                ids.append(self.inv[part.encode()]); continue
            for m in re.finditer(PAT, part):
                for tok in self._bpe([bytes([b]) for b in m.group().encode("utf-8")]):
                    ids.append(self.inv[tok])
        return ids

    def encode_iterable(self, lines):           # memory test: never materialize the whole file
        for line in lines:
            yield from self.encode(line)

    def decode(self, ids):
        return b"".join(self.vocab[i] for i in ids).decode("utf-8", errors="replace")

Decode must concatenate bytes and then decode once: a multi-byte UTF-8 character may be split across tokens, so decoding token by token produces replacement characters (test_roundtrip_unicode_string exists for exactly this).

Corpus: low low low lower lowest newer wider new, counted per pre-token. Each step counts adjacent pairs (right), merges the most frequent one (ties to the lexicographically greater pair), rewrites the words (left), and grows the vocabulary. 2.18 Decoding: temperature and top-p

@torch.no_grad()
def generate(model, prompt_ids, max_new_tokens, temperature=1.0, top_p=1.0, eos_id=None):
    ids = prompt_ids.clone()                                  # (1, T)
    for _ in range(max_new_tokens):
        logits = model(ids[:, -model.context_length:])[:, -1, :]      # last position: (1, V)
        probs = softmax(logits / temperature, dim=-1)
        if top_p < 1.0:
            sp, si = probs.sort(descending=True)
            keep = sp.cumsum(-1) - sp < top_p                 # smallest set with mass ≥ top_p (keep the first)
            sp = torch.where(keep, sp, torch.zeros_like(sp))
            probs = torch.zeros_like(probs).scatter(-1, si, sp / sp.sum(-1, keepdim=True))
        nxt = torch.multinomial(probs, 1)                     # (1, 1)
        ids = torch.cat([ids, nxt], dim=1)
        if eos_id is not None and nxt.item() == eos_id:
            break
    return ids

3. Backprop from scratch in numpy (the CS231n drill)

Some interviews skip PyTorch and ask for a backward pass in plain numpy. CS231n's backpropagation notes give the recipe: break the function into a graph of simple gates, run forward and cache every intermediate, then walk the graph backward multiplying each incoming gradient by the gate's local gradient (the chain rule, applied one node at a time). The local gradients to know cold:

GateForwardLocal gradientBackward intuition
addq = x + y∂q/∂x = ∂q/∂y = 1distributes the incoming gradient unchanged to both inputs
multiplyf = q·z∂f/∂q = z, ∂f/∂z = qswaps the inputs: each input gets the other input times the gradient
maxm = max(x, y)1 for the larger input, 0 for the otherroutes the gradient to whichever input won in the forward pass
sigmoids = σ(x)s·(1−s)reuse the forward output; no need to recompute exp
matmulY = X WdX = dY Wᵀ, dW = Xᵀ dYshapes tell you where the transpose goes — check them, don't memorize

Animation: a computational graph, forward then backward

The CS231n example f(x, y, z) = (x + y) · z at x=−2, y=5, z=−4. Forward fills values left to right; backward fills gradients right to left: ∂f/∂f = 1, the multiply gate hands z = −4 to q and q = 3 to z, the add gate passes −4 through to both x and y. Every backward step is "incoming gradient × local gradient" — nothing else.

import numpy as np

def mlp_forward_backward(X, y_onehot, W1, b1, W2, b2):
    """Two-layer MLP, ReLU hidden, softmax + cross-entropy. Returns loss and gradients.
    X: (N, D)  W1: (D, H)  b1: (H,)  W2: (H, C)  b2: (C,)"""
    N = X.shape[0]
    # ---- forward, caching everything we need ----
    z1 = X @ W1 + b1                      # (N, H)
    h = np.maximum(z1, 0)                 # (N, H)  ReLU
    z2 = h @ W2 + b2                      # (N, C)  logits
    z2 = z2 - z2.max(axis=1, keepdims=True)
    p = np.exp(z2); p /= p.sum(axis=1, keepdims=True)          # softmax (N, C)
    loss = -np.log((p * y_onehot).sum(axis=1) + 1e-12).mean()
    # ---- backward: chain rule gate by gate ----
    dz2 = (p - y_onehot) / N              # softmax+CE gradient — the one identity worth memorizing
    dW2 = h.T @ dz2                       # (H, C)
    db2 = dz2.sum(axis=0)                 # (C,)
    dh = dz2 @ W2.T                       # (N, H)
    dz1 = dh * (z1 > 0)                   # ReLU routes gradient where it was active
    dW1 = X.T @ dz1                       # (D, H)
    db1 = dz1.sum(axis=0)                 # (H,)
    return loss, dict(W1=dW1, b1=db1, W2=dW2, b2=db2)

def grad_check(f, param, grads, eps=1e-5, n=5):
    """Compare analytic grads against centered differences on a few random entries."""
    for _ in range(n):
        idx = tuple(np.random.randint(s) for s in param.shape)
        old = param[idx]
        param[idx] = old + eps; lp = f()
        param[idx] = old - eps; lm = f()
        param[idx] = old
        num = (lp - lm) / (2 * eps)
        print(idx, num, grads[idx], abs(num - grads[idx]) / (abs(num) + abs(grads[idx]) + 1e-12))

The interview-grade talking points: the softmax-with-cross-entropy gradient collapses to p − y; ReLU's backward is a mask, so dead units get zero gradient forever; every dW is "input transposed times upstream gradient" and the shapes force the transpose; and a centered finite-difference check with relative error below 1e-5 is how you prove it in two minutes.

4. Classic ML from scratch

These come up in both ML-coding and "traditional ML" screens. Each is written to be typed in a few minutes with the complexity stated.

def kmeans(X, k, iters=100, seed=0):               # O(iters · N · k · D)
    rng = np.random.default_rng(seed)
    C = X[rng.choice(len(X), k, replace=False)]      # init: k random points (k-means++ is the upgrade)
    for _ in range(iters):
        d = ((X[:, None, :] - C[None, :, :]) ** 2).sum(-1)     # (N, k) squared distances
        a = d.argmin(1)                                        # assignment step
        newC = np.stack([X[a == j].mean(0) if np.any(a == j) else C[j] for j in range(k)])
        if np.allclose(newC, C): break
        C = newC                                               # update step
    return C, a

def logistic_regression(X, y, lr=0.1, epochs=500, l2=0.0):   # O(epochs · N · D)
    w, b = np.zeros(X.shape[1]), 0.0
    for _ in range(epochs):
        p = 1 / (1 + np.exp(-(X @ w + b)))                     # sigmoid
        g = p - y                                              # dL/dz for BCE, same shape as y
        w -= lr * (X.T @ g / len(y) + l2 * w)
        b -= lr * g.mean()
    return w, b

def knn_predict(Xtr, ytr, Xte, k=5):                 # O(N_te · N_tr · D) — no training, all inference
    d = ((Xte[:, None, :] - Xtr[None, :, :]) ** 2).sum(-1)
    nn_idx = np.argpartition(d, k, axis=1)[:, :k]
    votes = ytr[nn_idx]
    return np.array([np.bincount(v).argmax() for v in votes])

def decision_stump(X, y):                            # O(D · N log N): best single threshold split
    best = (np.inf, None, None)
    for j in range(X.shape[1]):
        order = np.argsort(X[:, j]); xs, ys = X[order, j], y[order]
        for i in range(1, len(xs)):
            if xs[i] == xs[i - 1]: continue
            left, right = ys[:i], ys[i:]
            gini = sum(len(s) / len(y) * (1 - ((np.bincount(s) / len(s)) ** 2).sum()) for s in (left, right))
            if gini < best[0]: best = (gini, j, (xs[i] + xs[i - 1]) / 2)
    return best                                       # (impurity, feature, threshold)

def pca(X, n_components):                             # O(N · D²) via SVD of the centered data
    Xc = X - X.mean(0)
    U, S, Vt = np.linalg.svd(Xc, full_matrices=False)
    components = Vt[:n_components]                     # principal directions (n_components, D)
    explained = S[:n_components] ** 2 / (S ** 2).sum()
    return Xc @ components.T, components, explained

def beam_search(model, prompt_ids, beams=4, max_new_tokens=20, length_penalty=1.0):
    live = [(0.0, prompt_ids)]                                    # (log-prob, ids)
    for _ in range(max_new_tokens):
        cand = []
        for lp, ids in live:
            logp = torch.log_softmax(model(ids)[:, -1, :], dim=-1)[0]      # (V,)
            top_lp, top_i = logp.topk(beams)
            for l, i in zip(top_lp.tolist(), top_i.tolist()):
                cand.append((lp + l, torch.cat([ids, torch.tensor([[i]])], dim=1)))
        live = sorted(cand, key=lambda c: c[0] / (c[1].shape[1] ** length_penalty), reverse=True)[:beams]
    return live[0][1]
