Math Foundations for Deep Learning

Everything in this track — attention, backprop, quantization, roofline models — reduces to four pieces of math: linear algebra, calculus, probability, and floating-point arithmetic. This chapter builds each one from intuition to the exact form you will meet again in later chapters.

1. Linear algebra: vectors, dot products, and matrices

A vector is just an ordered list of numbers, but deep learning leans on its geometric reading: a point (or arrow) in a space with one axis per number. A 4096-dimensional embedding is an arrow in a 4096-dimensional space, and "two tokens mean similar things" becomes "two arrows point in similar directions". The tool that measures this is the dot product:

a · b = Σᵢ aᵢbᵢ = |a| |b| cos θ

Both forms matter. The sum form is what hardware computes — a multiply-accumulate, the single operation GPUs are built around (one FMA = 2 FLOPs). The cosine form is what the number means: positive when the vectors agree, zero when they are orthogonal (unrelated), negative when they oppose. Divide out the lengths and you get cosine similarity, the standard "how alike are these embeddings" metric in retrieval. And every attention score you will meet in the Attention chapter is exactly this: a query vector dotted with a key vector, asking "how relevant is that token to me?"

Matrices are functions, not grids

The productive way to read a matrix is as a linear map: a function that takes a vector in and gives a vector out, where the columns of the matrix tell you where the basis vectors land. Multiply a 2×2 matrix by every point of a unit square and the square becomes a parallelogram: rotations, stretches, shears — any combination, as long as lines stay lines and the origin stays put. The determinant is the area-scaling factor of that map (negative when the map flips orientation; zero when it squashes the plane into a line, destroying information — which is why det = 0 means "not invertible").

A neural network layer y = Wx + b is exactly this: a linear reshaping of space, followed by a shift. Everything a plain linear layer can do to data, you can see in the animation below.

Matrix multiplication: composition, and 2mnk FLOPs

Multiplying two matrices composes the two maps: (AB)x = A(Bx) — apply B, then A. Elementwise, each output entry is a dot product between a row of A and a column of B:

for i in range(m): # each output row for j in range(n): # each output column acc = 0.0 for l in range(k): # one dot product acc += A[i][l] * B[l][j] # 1 multiply + 1 add = 2 FLOPs C[i][j] = acc

Count the work: m·n output entries, each needing k multiply-adds, so 2·m·n·k FLOPs. For a square n×n matmul that is 2n³ — cubic growth, which is why a 4096×4096×4096 multiply is already 137 GFLOP, and why the GPU chapter is largely the story of making this one loop nest fast. Memorize 2mnk: it is the numerator of every arithmetic-intensity and MFU calculation you will ever do.

Deep learning is matmul all the way down: a batch of activations times a weight matrix (linear layers), queries times keys (attention scores), scores times values (attention output). The reason is partly mathematical (linear maps compose and differentiate cleanly) and partly economic — matmul's O(n³) compute over O(n²) data is the rare workload dense enough to keep arithmetic units busy, so hardware evolved to serve it, so architectures evolved to use it.

2. Calculus: derivatives, the chain rule, and gradient descent

A derivative answers one question: if I nudge the input a little, how much does the output move? f′(x) = 3 means a nudge of 0.01 in x moves f by about 0.03. That "sensitivity" reading scales up to millions of inputs: for a function of many variables — say, a loss as a function of every weight in a network — the gradient ∇L collects all the partial sensitivities into one vector, and that vector points in the direction of steepest increase. Training is then almost embarrassingly simple: repeatedly step the other way.

w ← w − η ∇L(w) # η = learning rate

The chain rule is how we get the gradient through a composition of functions — and a deep network is nothing but a composition of functions:

L = f(g(h(x))) ⇒ dL/dx = f′(g(h(x))) · g′(h(x)) · h′(x)

Each factor is local: a layer only needs to know how its own output responds to its own input. Multiply the local factors along the path from the loss back to any weight and you have that weight's gradient. That observation — compute the factors once, back to front, reusing shared prefixes — is backpropagation, and the Deep Learning chapter animates it edge by edge. 3. Probability and information theory

A language model's entire output is a probability distribution: given the context, a probability for every token in the vocabulary. Three tools govern how we create, sample, and train such distributions.

Softmax: scores → probabilities, with a temperature knob

Models produce raw scores ("logits") — any real numbers. Softmax converts them to a valid distribution while keeping their order:

softmax(zᵢ / T) = exp(zᵢ/T) / Σⱼ exp(zⱼ/T)

The temperature T reshapes confidence without changing ranking: T → 0 puts all mass on the argmax (greedy decoding), T = 1 uses the model's native confidence, large T flattens toward uniform (more diverse, less accurate sampling). This one function is the last layer of every LLM, the normalizer inside attention, and the sampling knob in every inference API.

Cross-entropy: the loss behind next-token prediction

Information theory measures the surprise of an outcome with probability p as −log p: certain events carry no surprise, rare events carry a lot. The entropy H(p) is the average surprise of a distribution — how unpredictable it is. The cross-entropy between the true distribution p and a model q is the average surprise you feel when reality is drawn from p but you expected q:

H(p, q) = − Σᵢ pᵢ log qᵢ = H(p) + KL(p ‖ q)

The decomposition on the right is the key: cross-entropy equals the irreducible entropy of the data plus the KL divergence — the extra surprise caused purely by your model being wrong. Minimizing cross-entropy therefore minimizes KL: it drives the model's distribution toward the data's.

Now the punchline for LLMs. During pretraining the "true" distribution for each position is one-hot (the actual next token had probability 1), so the sum collapses to a single term: the loss is just −log q(correct token) — the model's surprise at the token that actually came next, averaged over trillions of positions. All of pretraining is: be less surprised by the internet. The per-token loss exponentiated, e^loss, is the perplexity you see in papers — "the model was as confused as if choosing uniformly among that many tokens."

KL divergence returns in post-training: RLHF and DPO (see Training) add a KL penalty against the base model so the tuned policy improves rewards without drifting far from the distribution it learned in pretraining.

4. Numerical computing: the float, and the trick that makes softmax work

Real hardware does not compute with real numbers; it computes with floating point — scientific notation in binary. A float is a sign bit, an exponent (which power-of-two window you are in), and a mantissa (where you sit inside that window):

FormatBits (sign/exp/mantissa)Max valueWhat the split means
FP321 / 8 / 23~3.4×10³⁸The default: wide range and ~7 decimal digits of precision
FP161 / 5 / 1065,504Precise but narrow-ranged — overflows easily, needs loss scaling
BF161 / 8 / 7~3.4×10³⁸FP32's range, 3 decimal digits — the training default: range beats precision

Two consequences matter everywhere. First, floats have relative precision: the gap between adjacent representable numbers grows with magnitude, so adding a tiny gradient to a large weight can round to nothing — one reason optimizers keep FP32 "master" copies of weights during BF16 training. Second, exp() overflows catastrophically: e⁸⁹ already exceeds FP32's max, and attention logits routinely get that large.

Softmax as written is therefore numerically broken. The fix exploits an invariance — shifting all logits by a constant cancels in the ratio — so you subtract the max first:

# naive: exp overflows → inf/inf → NaN softmax(z) = exp(z) / sum(exp(z)) # stable: largest exponent is exp(0) = 1, nothing overflows m = max(z) softmax(z) = exp(z − m) / sum(exp(z − m))

Hold onto this trick: the Kernels chapter's online softmax — the heart of FlashAttention — is this same max-subtraction performed incrementally, updating m and the running sum as each block of scores streams through on-chip memory, so the full score matrix never has to exist at once.
