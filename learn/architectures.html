LLM Architecture Evolution

Every architectural development since GPT-2 that survived contact with scale: what changed, why it won, and what it costs at inference time. This chapter assumes the transformer block and attention variants; here we track how the whole organism evolved.

1. The dense lineage: GPT-2 → Llama 3 as a sequence of small wins

Strip away scale, and the modern dense LLM differs from GPT-2 (2019) by half a dozen targeted substitutions. None is dramatic alone; together they are the difference between a model that trains unstably at 1B and one that trains cleanly at 400B. The honest way to read this table is as a list of fixes, each motivated by a failure at larger scale:

The meta-lesson: architecture changes get adopted when they fix a training-stability problem or an inference-cost problem — almost never because they raise benchmark scores at small scale. GQA and MLA entered pretraining purely because of the serving math you saw in the KV-cache section.

2. Mixture of Experts: paying for capacity, not per token

A dense model spends every parameter on every token. MoE breaks that coupling: replace the MLP with E expert MLPs and a tiny router that sends each token to its top-k experts. Total parameters grow with E (knowledge capacity); per-token FLOPs grow only with k (compute cost). DeepSeek-V3 is the canonical modern datapoint: 671B total parameters, 37B active per token — GPT-4-class capacity at mid-size compute.

The engineering is all in the routing:

  • Top-k softmax routing: router logits → pick k experts → weight their outputs by the (re-normalized) router probabilities. Mixtral uses top-2 of 8; DeepSeek top-8 of 256 fine-grained experts plus one always-on shared expert for common knowledge, so routed experts can specialize.
  • Load balancing: left alone, routers collapse onto a few favorite experts, starving the rest (dead experts) and overloading devices. Classic fix: an auxiliary balance loss pushing uniform usage — which fights quality. DeepSeek-V3's aux-loss-free balancing instead adjusts a per-expert bias only for routing decisions, leaving gradients clean.
  • The systems bill: experts live on different GPUs, so every MoE layer costs two all-to-alls (dispatch and combine) — the expert-parallelism animation in Chapter 10. Serving MoE well is why DeepEP/EPLB exist, and why the NKI Library ships dedicated MoE kernels for both prefill (CTE) and decode (TKG).

3. Before transformers: RNNs and LSTMs (and why attention won)

Every "why transformers?" interview answer is really a comparison with recurrent networks, so it pays to know them properly. A vanilla RNN processes a sequence one step at a time, carrying a hidden state h_t ∈ ℝ^H that is updated from the current input and the previous state with weights shared across time:

h_t = tanh(W_x·x_t + W_h·h_{t−1} + b), y_t = W_out·h_t + b_out

Training unrolls the recurrence and backpropagates through time (BPTT). The Jacobian between consecutive states is ∂h_t/∂h_{t−1} = diag(tanh′(z_t))·W_h, and the gradient reaching step t from a loss at step T is a product of T−t such factors. tanh′ ∈ (0, 1] only shrinks, and repeated multiplication by W_h either shrinks or blows up depending on its largest singular value — so gradients across long gaps vanish or explode, and a vanilla RNN cannot learn dependencies more than a few dozen steps long. Gradient clipping handles the exploding side; nothing in the vanilla cell fixes vanishing.

The LSTM fixes it by splitting memory from output. A cell state c_t flows along a "highway" touched only by element-wise gates — no matmul, no squashing nonlinearity between steps — while the hidden state h_t is a filtered view of it that is both the cell's output and its own query for the next step's gates:

f_t = σ(W_f·[h_{t−1}, x_t] + b_f) forget: what to erase i_t = σ(W_i·[h_{t−1}, x_t] + b_i) input: what to write c̃_t = tanh(W_c·[h_{t−1}, x_t] + b_c) candidate content c_t = f_t ⊙ c_{t−1} + i_t ⊙ c̃_t cell update (the constant-error carousel) o_t = σ(W_o·[h_{t−1}, x_t] + b_o) output: what to expose h_t = o_t ⊙ tanh(c_t)

Because ∂c_t/∂c_{t−1} = f_t, as long as the forget gate stays near 1 the gradient travels backward many steps essentially intact — this is the whole trick. The GRU is the two-gate simplification (reset and update gates, no separate cell state) that trains a bit faster with similar quality. Both still have the structural limits that attention removed.

Animation: gradients through time — RNN vs LSTM

An unrolled 16-step network with the loss at the last step. Bars show (log scale) how much gradient reaches each earlier step. In the vanilla RNN the factor per step is roughly ρ · tanh′: below 1 the signal dies within ~10 steps, above 1 it explodes. Switch to the LSTM: the cell-state path multiplies by the forget gate alone, so with f ≈ 0.95 half the signal survives 14 steps and with f → 1 all of it does — the constant-error carousel.

Transformers won on two counts the table makes plain: parallel training that saturates accelerators, and direct O(1) paths for long-range dependencies. The cost was the growing KV cache — which is exactly the pressure that brought recurrence back in modern dress as state-space models and gated linear attention (next section). Knowing the LSTM gate equations is not nostalgia: Mamba's selective gates and Gated DeltaNet's forgetting gates are the same idea with hardware-friendly math.

4. State-space models: Mamba and the case against the KV cache

Attention's superpower is also its bill: a cache that grows linearly with context and a decode step that must re-read all of it (Ch. 9). State-space models make the opposite trade: compress the entire past into a fixed-size recurrent state. Decode cost and memory are then constant in sequence length.

Mamba's contribution (over earlier S4-style SSMs) is selectivity: the state-transition and input gates are functions of the current token, so the model can choose what to write into its state and what to forget — recovering some of attention's content-based addressing. Mamba-2 (SSD) then showed the selective scan can be computed with matmul-shaped primitives (semiseparable matrices), making it tensor-core friendly and revealing a formal duality with linear attention. Training parallelism comes from the associative scan — the same parallel-scan primitive you built in the kernels chapter.

The honest scorecard: SSMs win on long-context throughput and memory; pure SSMs lag attention on exact recall ("needle in a haystack", copying, in-context lookup) because a fixed state must lossily compress the past. Which is why the production answer became…

Hybrids. Interleave mostly-SSM (or linear-attention) layers with a few full-attention layers: the SSM layers carry cheap sequence mixing, the sparse attention layers provide exact recall. Jamba, Nemotron-H, Falcon-H1, Bamba, IBM Granite 4, and Kimi-Linear (hybrid with Gated DeltaNet-style linear attention) all follow this recipe — and you already met Gated DeltaNet, Mamba-2 SSD, and linear/selective scans as kernels in the NKI Library's experimental catalog: new architectures become real exactly when someone writes fast kernels for them.

Animation: KV cache vs recurrent state

Both models read the same stream. Top: attention appends every token's K,V — memory grows, and each step re-reads it all. Bottom: the SSM folds each token into a fixed-width state (watch it update in place — older contributions fade). Constant memory, constant step cost; the price is that faded information is gone unless a hybrid's attention layer can still see it.

5. Linear attention and sliding windows: cheaper mixers

Two other families attack the same O(n²)/O(n) costs without abandoning attention entirely:

  • Linear attention replaces softmax(QKᵀ)V with feature-mapped φ(Q)(φ(K)ᵀV), which associativity turns into a running (d×d) state — recurrent at decode, parallel at training. Modern gated variants (GLA, Gated DeltaNet, RWKV's line) add forgetting and delta-rule updates that fix the early versions' quality gap. Mamba-2's duality result means this family and SSMs are near-relatives.
  • Sliding-window attention keeps exact softmax attention but only over the last w tokens: O(n·w), cache capped at w. Alone it loses global context; in a hybrid ratio it's the current mainstream — Gemma 3 runs 5 local layers per 1 global, GPT-OSS alternates banded and dense layers, Mistral popularized w=4K windows. The global layers (often RoPE-less or long-RoPE) carry document-scale information; local layers do the bulk of mixing cheaply.

Pattern to remember for interviews: full attention is becoming a scarce resource spent on a few layers, with cheap mixers (windows, SSMs, linear attention) doing everything else. Serving engines mirror this: a hybrid's cache is a mix of per-layer ring buffers (windows), constant states (SSM), and real paged KV (full layers).

6. Multi-token prediction and architecture-for-inference

DeepSeek-V3 trains an auxiliary MTP head: at each position the model also predicts the token after next, through a small extra transformer block. Training signal densifies (slightly better model), but the real payoff is serving: the MTP head is a built-in draft model for speculative decoding — self-speculation with high acceptance, no separate draft model to deploy. Medusa and EAGLE (Ch. 9) are the bolt-on versions of the same idea.

This is the clearest example of a broader shift: architectures are now co-designed with their inference systems. MLA exists to shrink the cache; fine-grained MoE assumes expert parallelism; window/global ratios are tuned against paged-KV implementations; MTP assumes a speculative scheduler. Reading a model card now means reading its serving plan.

7. Multimodal architectures

Three dominant patterns, in increasing order of integration:

  • Encoder + projector (LLaVA pattern): a pretrained vision encoder (ViT/SigLIP) turns the image into patch embeddings; a small projector (MLP or cross-attention resampler) maps them into the LLM's embedding space as "image tokens"; the LLM is then fine-tuned on interleaved data. Cheap, modular, and still the workhorse — Llama-Vision, Qwen-VL, Pixtral, InternVL all descend from it. Resolution handling (tiling, any-res) decides most of the quality.
  • Early-fusion / native multimodal: one transformer consumes text, image (and audio/video) tokens from the start of pretraining — unified representation, better cross-modal reasoning, much more expensive to train. Gemini-class and GPT-4o-class models, and open models like Gemma 3n with audio (the plan's Axolotl list includes Voxtral for audio).
  • Generation-side: diffusion or autoregressive image decoders bolted to the same trunk — outside this plan's scope, but the serving implication isn't: image tokens are thousands of prefill tokens, making multimodal serving prefill-heavy (Ch. 9's chunked prefill matters even more; see vLLM's multimodal-inputs doc from Step 12).

8. The current frontier, honestly labeled

  • Reasoning-era training (o1/R1 lineage): long chain-of-thought via RL (GRPO, Ch. 11). Architecturally mostly unchanged — the innovation is post-training + test-time compute, and the serving impact is huge: thousands-of-token "thinking" generations shift load decode-ward.
  • Text diffusion LMs: generate by iterative denoising of whole sequences instead of left-to-right AR — parallel token generation, very different serving profile. Real research momentum (and an Axolotl training feature), not yet a production default.
  • Sparse attention at pretraining time: DeepSeek's NSA and sparse indexers (an NKI experimental kernel) train the sparsity pattern instead of retrofitting it.
  • What hasn't changed: tokenizer+embedding → repeated mixer/MLP blocks with residuals and norms → LM head. Every winner since 2019 is still that shape. Bet on components changing, not the shape.

9. Generation paradigms and thinking modes: CLM, masked and diffusion LMs, System 1 vs System 2

Everything above assumed one way of producing text: predict the next token, left to right, one forward pass per token. That is a choice, and it is worth seeing the alternatives clearly — both because they are now shipping (diffusion language models) and because the biggest capability jump of the last two years came not from a new block but from changing how long the model thinks before it answers.

8.1 Training objectives as paradigms: CLM, MLM, and the middle ground

Causal language modeling (CLM) is the GPT lineage: a decoder-only transformer with a causal mask, trained to predict token t+1 from tokens 1…t. It won for generation for three unglamorous reasons. One objective covers every task that can be phrased as text continuation. Every position in every sequence is supervised in a single pass, so no training tokens are wasted. And sampling is trivial: the training-time computation is the inference-time computation, just fed its own outputs. The causal mask also hands you incremental decoding for free — the KV cache exists only because earlier tokens never look at later ones, so their keys and values never change.

Masked language modeling (MLM) is the BERT lineage: corrupt ~15% of tokens, let every position attend bidirectionally, predict the masked ones. Bidirectional context makes it a superb encoder — embeddings, classification, retrieval still lean on it — but it is awkward for generation: you must decide how many tokens to emit and iteratively fill them, and only 15% of positions carry loss per pass. Prefix-LM and encoder–decoder models (T5, and UL2's "mixture of denoisers" that trains span corruption, prefix-LM, and extreme masking together) sit in between: bidirectional over the prompt, causal over the output. They remain strong for sequence-to-sequence tasks and are the shape of most speech and translation systems (the Deepgram encoder–decoder in Ch. 15 is one).

The serving column is the one to memorize: only CLM gets incremental decoding for free. Bidirectional models recompute every position every pass. That is why the engines in Ch. 11 are built around CLM, and why diffusion LMs need their own serving stack.

8.2 Diffusion language models: generating a whole canvas at once

Diffusion for text comes in two families, and the acronym CDM is used for two different things, so keep the terms straight:

  • Discrete / masked diffusion (LLaDA, Dream, Mercury, Gemini Diffusion, LLaDA2/MoE variants): the "noise" is masking. Training masks a random fraction of tokens (uniformly from 0 to 100%, not a fixed 15%) and predicts them with a bidirectional transformer; the objective is a weighted MLM averaged over mask ratios, and it is a proper likelihood bound. Generation starts from an all-masked canvas and, over T steps, unmasks the tokens the model is most confident about, optionally re-masking low-confidence ones so later steps can revise them. Several tokens are revealed per step, so the number of forward passes is T, not the sequence length.
  • Continuous diffusion models (CDM) (Diffusion-LM, CDCD, Plaid, and the embedding-space line): add Gaussian noise to token embeddings (or logits) and denoise in continuous space exactly as image diffusion does; the hard part is the final "rounding" from a continuous vector back to a discrete token, which is where most quality is lost. The other reading of CDM — a conditional diffusion model, any diffusion model conditioned on text, class, or an image, as in Stable Diffusion — is a statement about conditioning, not about the data being continuous. When a paper says CDM, check which it means.

The serving profile is the mirror image of CLM. A diffusion LM produces an entire block of tokens in parallel, in a fixed number of passes that you choose at inference time (fewer steps = faster, rougher), with no KV cache and no sequential dependency — which makes it excellent for infilling and editing (it sees both sides of the gap) and for latency-sensitive short generations (Mercury reports thousands of tokens per second on H100s). The known weaknesses are exact long-range coherence over long outputs, reliable variable-length generation, and the loss of the free incremental cache. Block diffusion (BD3-LM style) is the hybrid: generate block by block autoregressively, but denoise each block in parallel — reclaiming a KV cache across blocks while keeping parallel decoding within them, much as speculative decoding verifies a block of drafts at once (Ch. 11).

8.3 System 1 and System 2: fast pattern completion vs deliberate computation

Kahneman's split between System 1 (fast, automatic, pattern-matching) and System 2 (slow, effortful, sequential) maps cleanly onto language models. A standard CLM answering directly is pure System 1: one forward pass per token, a fixed amount of computation regardless of how hard the question is, and an answer that is a pattern completion of the prompt. Nothing in the architecture lets the model spend more compute on a harder problem.

System 2 behavior is test-time compute. The cheapest version is prompting: chain-of-thought makes the model write intermediate steps, so each later token conditions on scratch work — compute scales with the length of the reasoning. Self-consistency samples several chains and votes. Search and verification (tree search over partial solutions, a verifier or process-reward model scoring steps, best-of-N with a checker) spend still more. And the reasoning models — o1/o3, DeepSeek-R1, Qwen3 in thinking mode, Gemini's thinking variants — bake the behavior in: they are trained with RL on verifiable rewards to produce long private "thinking" before the visible answer, and their accuracy rises with the number of thinking tokens they are allowed (Ch. 13 covers the GRPO recipe). Architecturally these are ordinary CLMs; what changed is the policy, and the serving bill: thousands of decode tokens per query, which pushes load firmly decode-ward (Ch. 11).

Three refinements matter in practice. Thinking budgets cap the private tokens (an explicit latency/accuracy dial per request), and hybrid thinking modes ship one model that can run either way — Qwen3's /think and /no_think, Claude's extended thinking, Gemini's thinking budgets — so a product routes easy requests to System 1 and hard ones to System 2. Latent reasoning moves the deliberation out of the token stream: Coconut ("chain of continuous thought") feeds the last hidden state back as the next input embedding so the model reasons in vector space without decoding words, and the looped / depth-recurrent models from the developments table (Ouro's four passes over one stack, Nanbeige's two) do System 2 inside the forward pass by iterating the same layers until a learned exit gate fires — compute that scales with difficulty, with no visible chain at all.

Finally, the loop closes with System 2 distillation: run the slow method, keep the outputs that pass a check, and fine-tune the model to produce them directly ("Distilling System 2 into System 1", Yu et al. 2024; DeepSeek's R1-distilled small models are the production example, and Ch. 14 treats this as a customization rung). It compiles deliberation back into fast pattern completion — with limits: distillation transfers the answers the teacher reached, not the ability to search for new ones, so held-out hard problems regress toward the student's System 1 ceiling.

8.4 The non-autoregressive frontier (research)

Beyond masked diffusion, three lines are trying to make whole-sequence generation competitive with CLM and are best read as research rather than tooling: flow-matching text models that learn a straight-line transport from noise to token embeddings (the same objective π0 uses for robot actions in Ch. 17); consistency-style models that collapse many denoising steps into one or two; and energy-based formulations that score whole sequences and sample by iterative refinement. All promise parallel, revisable generation; none has yet matched CLM at frontier scale on long-form coherence, which is why the practical answer today is "CLM for the backbone, diffusion for infilling and low-latency niches, System 2 via RL-trained thinking."
