Transformers & LLMs

From raw text to next-token prediction: tokenization, embeddings, the transformer block stage by stage, why deep stacks train at all, the objective, sampling, and how architectures evolved from GPT-2 to DeepSeek-V3. This is the model-side companion to the Attention and Inference chapters.

1. Tokenization: text becomes integers

A language model never sees letters. It sees a sequence of integers, each naming an entry in a fixed vocabulary of strings called tokens. The dominant algorithm, byte-pair encoding (BPE), builds that vocabulary by brute statistics: start with single bytes, find the most frequent adjacent pair in a training corpus, merge it into a new token, repeat tens of thousands of times. Frequent words ("the", "ing", " and") end up as single tokens; rare words split into familiar pieces. The learned merge list is the tokenizer: to encode new text, apply the merges greedily in the order they were learned.

The design trade-off is vocabulary size. A bigger vocabulary (Llama-3 uses 128K tokens, GPT-2 used 50K) means fewer tokens per sentence — which means less compute and less KV cache per request, since every cost in the inference chapter scales with token count — but a bigger embedding table and a bigger final projection. English averages roughly 3.5–4.5 characters per token with modern tokenizers.

Tokenization explains several famous LLM quirks. Models struggle to count the r's in "strawberry" because they never see letters — "strawberry" may be one or two tokens, and the model must have memorized facts about its spelling rather than reading it. Arithmetic suffers when digit sequences split inconsistently ("1234" as 12|34 but "1235" as 1|235), which is why modern tokenizers special-case digits. And trailing whitespace can change everything, because " the" and "the" are different tokens with different statistics.

2. Embeddings: integers become vectors

Each token id indexes a row of an embedding matrix E ∈ ℝV×d (vocabulary × model width). That row — say d = 4096 numbers for Llama-3-8B — is the token's initial representation, and it is learned like every other weight: tokens that behave similarly in training end up with nearby vectors, which is why directions in embedding space encode meaning (the classic king − man + woman ≈ queen). From here on, the entire transformer is a machine that repeatedly refines these d-dimensional vectors: the vector at position i gradually stops meaning "the token at position i" and starts meaning "everything the context implies at position i".

One problem: attention, the only operation that mixes positions, is permutation-invariant — shuffle the input vectors and you shuffle the outputs identically. The model cannot know word order unless positions are injected explicitly. GPT-2 added a learned vector per absolute position; modern models rotate queries and keys by position-dependent angles (RoPE), which encodes relative position and is covered with an animation in the attention chapter.

3. The transformer block, stage by stage

A decoder-only LLM is an embedding layer, N identical blocks (32 for an 8B model, 126 for DeepSeek-V3), and a final projection back to vocabulary logits. Each block does two things: attention (positions exchange information) and an MLP (each position processes what it gathered, independently). Both are wrapped in residual connections and preceded by normalization. That's the whole trick, repeated N times.

Animation: one block, end to end

Five tokens flow through one block. Watch the attention stage build the 5×5 score matrix — the greyed upper triangle is the causal mask: position i may only attend to positions ≤ i, which is what makes the model autoregressive (and what makes the KV cache possible). Softmax turns each surviving row into weights; the weighted sum of value vectors is what each token "learns" from its past.

Reading the stages precisely, with x ∈ ℝn×d the block input:

h = x + Attention(RMSNorm(x)) # positions talk
out = h + MLP(RMSNorm(h)) # positions think

Attention(x) = softmax(QKᵀ/√d_head + causal_mask) · V, Q = xW_Q, K = xW_K, V = xW_V
MLP(x) = (SiLU(xW_gate) ⊙ xW_up) W_down # SwiGLU; hidden dim ≈ 2.7–4× d

The MLP holds most of the parameters (~⅔ in a dense model) and is where factual knowledge appears to be stored; attention is the routing system that moves information to where the MLP can use it. Scaling by 1/√d_head keeps dot products in a range where softmax has useful gradients.

4. Why 100-layer stacks train: residuals and norms

Without residual connections, stacking 100 layers multiplies 100 Jacobians, and gradients vanish or explode (the deep learning chapter shows this happening). The residual form x + f(x) changes the geometry: there is an identity path from the loss to every layer, so gradients flow undiminished, and each block only has to learn a correction to a running "residual stream" rather than a full transformation. A productive mental model: the residual stream is a shared communication bus of width d; attention heads and MLPs read from it, compute, and write their contribution back by addition.

Normalization keeps the stream's scale stable so corrections from layer 90 are commensurate with those from layer 2. Modern LLMs use RMSNorm (rescale by the root-mean-square, learned gain, no mean subtraction — cheaper than LayerNorm, works as well) and place it before each sublayer (pre-norm). Pre-norm leaves the residual path completely clean — the identity is never normalized away — which is why GPT-2-era post-norm needed careful warmup while pre-norm models train stably at much greater depth. You already met RMSNorm as a kernel-fusion target in the study plan's Liger notebook: norm + projection fuse into one memory pass (see Kernels).

5. The objective: predict the next token

Training is self-supervised: every position in every text is a labeled example whose label is simply the next token. The model outputs logits over the vocabulary at every position simultaneously, and the loss is the average cross-entropy between each position's prediction and the actual next token:

L = −(1/n) Σᵢ log p(xᵢ₊₁ | x₁..xᵢ) # one forward pass scores all n positions at once

This parallel scoring is called teacher forcing: position i is conditioned on the true prefix, not on the model's own earlier predictions, so the whole sequence trains in one pass — the same parallelism that makes prefill fast. The causal mask is what makes it legitimate, guaranteeing no position peeks at its own answer.

Perplexity is the exponential of this loss: PPL = eL, interpretable as "the model is as uncertain as if it were choosing uniformly among PPL options." A loss of 2.0 nats is PPL ≈ 7.4; frontier models reach low single digits on held-out web text. Pretraining at scale is governed by scaling laws — Chinchilla's ~20 tokens per parameter compute-optimal rule, now routinely exceeded (Llama-3-8B saw 15T tokens, ~1900 per parameter) because inference cost rewards over-training small models. The full pipeline from pretraining through SFT and preference tuning lives in the Training chapter.

6. Sampling: logits become text

At inference the model gives you a distribution; you decide how to pick from it. Greedy (argmax) is deterministic but repetitive and bland. Temperature T divides the logits before softmax: T < 1 sharpens toward the top tokens, T > 1 flattens toward uniform. Top-k keeps only the k most likely tokens; top-p (nucleus) keeps the smallest set whose probabilities sum to p — adaptive, keeping few tokens when the model is confident and many when it isn't. Production samplers compose these: temperature, then truncation, then renormalize and sample.

Mixture of experts deserves a sentence of intuition: replace the one big MLP with many smaller "expert" MLPs and a learned router that sends each token to its top-k experts. Parameters (knowledge) scale with the number of experts, while per-token FLOPs scale only with the k active ones — DeepSeek-V3 carries 671B parameters but each token touches 37B. The shared expert handles common patterns so routed experts can specialize; auxiliary losses (or V3's bias-adjustment trick) keep load balanced. The price is systems complexity — routing, all-to-all communication, expert placement — which is exactly the parallelism chapter's problem.

8. What a context window costs

"128K context" is a systems claim, not just a model claim. Attention FLOPs grow quadratically with context during prefill; the KV cache grows linearly and must survive for the whole generation — at 128K tokens, a Llama-3-70B conversation holds gigabytes of cache per user (compute it with the KV calculator). Everything in the serving stack — GQA/MLA above, paged allocation, cache quantization, prefix sharing — exists to pay this bill. When you read a model card, translate the context window into bytes-per-user before believing the concurrency numbers.

9. LLM accounting: parameters, activations, FLOPs and memory

Rapid-fire interviews love this material because it has exact answers. Alisa Liu's Book of LLMs keeps a running "accounting" page for it; this section is that page made interactive. Notation: V vocabulary, D model width, L layers, N query heads, K KV heads, H head dimension (D = N·H), F FFN width, B batch, S sequence length.

Parameters

Per decoder block: attention is Q: D×D, K: D×KH, V: D×KH, O: D×D, i.e. 2D² + 2·D·K·H, which is 4D² for full MHA (K = N) and noticeably less under GQA. A SwiGLU FFN has three matrices (gate, up, down) of D×F, so 3DF; with the Llama convention F ≈ 8D/3 that is 8D². Two RMSNorms contribute 2D. Embeddings are V×D, and so is the unembedding unless the two are tied (GPT-2 ties them; Llama does not). Total:

params ≈ 2·V·D (untied; V·D if tied) + L·(4D² + 3DF + 2D) + D (final norm) ≈ 2VD + 12·L·D² for F = 8D/3, K = N

Worked check — Llama-3-8B (V=128,256, D=4,096, L=32, N=32, K=8, H=128, F=14,336): attention 16.78M·2 + 4.19M·2 = 41.9M; FFN 3·4096·14336 = 176.2M; norms 8K → 218.1M per block; ×32 = 6.98B; plus 2·128256·4096 = 1.05B of embeddings and the final norm gives 8.03B, matching the published count. Notice embeddings are 13% of the model and the FFN is 80% of each block — the first thing to know when someone asks "where are the parameters?"

Activations (what training has to remember for backward)

Per layer, in tokens: the attention path stores the norm input and output (2BSD), Q, K, V (3BSD with MHA), the score matrix (B·N·S² — unless FlashAttention recomputes it), and the output (BSD); the FFN path stores its norm input (BSD), the gate and up outputs (2BSF ≈ 5.3BSD) and the down output (BSD). The Book's total is

activations per layer ≈ 14·B·S·D + B·N·S² (without FlashAttention; the S² term becomes B·N·S with it)

This is usually the dominant training-memory term, it scales with total tokens B·S, and gradient checkpointing trades it for recompute: keep only each layer's input and rebuild the rest during backward, roughly L·B·S·D instead of 14·L·B·S·D at ~33% extra compute (see the training-memory calculator).

FLOPs

Each matmul of an (m×k) by (k×n) costs 2mnk. Per layer in prefill: the four projections cost 8BSD² (MHA), QKᵀ and AV cost 2BS²D each, and the FFN 6BSDF ≈ 16BSD²; the unembedding adds 2BSDV once.

forward ≈ 2·B·S·D·(12·L·D + 2·L·S + V) → per token ≈ 2·(non-embedding params) + 2·D·V + 4·L·S·D (attention over S context)
backward ≈ 2 × forward (gradient w.r.t. inputs and w.r.t. weights, one matmul each) → training ≈ 6·N·D_tokens, the "6ND rule"

The attention term 4LSD per token is why long contexts become compute-bound in prefill even though the weight term dominates at short S; decode, by contrast, is bandwidth-bound (Ch. 11).

Memory

Inference = weights + KV cache + peak activations of one layer. Weights are params × bytes; the KV cache is 2·L·K·H·S·B·bytes (the calculator); peak activations are O(B·N·S² + B·S·F) in prefill without FlashAttention and O(B·N·S + B·F) in decode. Training in mixed precision, per parameter: 4 bytes FP32 master weights + 2 bytes BF16 working copy + 8 bytes Adam moments + 4 bytes FP32 gradient accumulation = 18 bytes/param (16 if you drop the transient BF16 copy, the figure most people quote), plus activations. A 7B model is therefore ~126 GB before a single activation — the arithmetic behind LoRA and ZeRO (Ch. 13).

Implementation notes (the muscle-memory details)

Alisa's notes are explicit that interviews ask you to write this, often with AI assistance off. The parts people fumble:

  • Causal masking: scores.masked_fill(~mask, -inf) before the softmax, with the convention that mask is True where attention is allowed (torch.tril). -inf rather than a large negative keeps the softmax exact.
  • RoPE: precompute cos(m·θᵢ) and sin(m·θᵢ) for every (position, pair) at init (θᵢ = base^(−2i/d)); apply by reshaping the head dimension into (H/2, 2) pairs and rotating (even, odd) with two multiplies each, then interleaving back with stack(...).flatten(-2). Rotate Q and K only, never V — position should affect who attends to whom, not what is passed.
  • The shape dance: project to (B, S, 3D), reshape to (B, S, 3, N, H), unbind Q/K/V, transpose(1,2) to (B, N, S, H), attend, transpose back, reshape to (B, S, D), output-project, add the residual.
  • Weight tying saves V·D parameters and acts as a regularizer at small scale; large models leave them untied because the input and output embeddings want different geometry.
  • Initialization: truncated normal with variance ~2/(d_in + d_out) for linear layers, and scaled-down (by depth) output projections so the residual stream's variance does not grow with layers; RMSNorm γ starts at 1.
  • Where FP32 lives: master weights, optimizer states, gradient accumulation, the softmax and cross-entropy (compute the log-sum-exp in FP32), and norm statistics. Everything matmul-shaped runs in BF16 (Ch. 10).
def scaled_dot_product_attention(q, k, v, mask): # q,k: (B, ..., S, d_k) v: (B, ..., S, d_v) d_k = q.shape[-1] scores = (q @ k.transpose(-2, -1)) / math.sqrt(d_k) # (B, ..., S, S) scores = scores.masked_fill(~mask, -torch.inf) # mask True = may attend return softmax(scores, dim=-1) @ v # softmax subtracts the row max internally

Gradient flow through sampling

Sampling a token is a discrete, non-differentiable step, so nothing downstream of a sample can send gradients back through it — which is exactly why RL post-training and RLHF need the score-function (REINFORCE) estimator: differentiate log π(a|s) weighted by a reward instead of differentiating through the sample (Ch. 17). Two other escape hatches show up in interviews. The Gumbel-max trick samples a categorical by adding Gumbel(0,1) noise to each logit and taking the argmax; Gumbel-softmax replaces that argmax with a temperature-τ softmax, giving a stochastic, approximately discrete, fully differentiable relaxation — low τ means near one-hot samples, high τ means smooth gradients. The straight-through estimator applies the non-differentiable function in the forward pass and pretends it was the identity in the backward pass; the gradient's magnitude is wrong but its direction is right for monotone functions like rounding, which is why quantization-aware training uses it (Ch. 10).
