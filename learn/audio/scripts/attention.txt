This is the deep dive on attention. The mechanism computed by hand, multi head attention and its cache saving variants, rotary position embeddings, and then the kernel that made long context affordable: FlashAttention, with its tiling and online softmax. If there is one chapter in this track where the math, the hardware, and the serving economics meet in a single idea, this is it.

Attention is a soft dictionary lookup. Each position emits a query, meaning "what am I looking for?" It also offers a key, meaning "what do I contain, as an address?" And a value, meaning "what do I contribute, as content?" A query is compared against every key by dot product, the natural "how aligned are we" measure from the math chapter. The comparisons become weights via softmax, and the output is the weight blended average of the values. Nothing is retrieved exactly. Everything is retrieved a little, in proportion to relevance.

The formula: attention of Q, K and V equals softmax of Q times K transposed, divided by the square root of the key dimension, times V. The shapes matter. Q and K are n by d, where n is the sequence length and d is the head dimension, typically sixty four to one hundred twenty eight. The product Q K transposed is n by n, one score for every pair of positions. The output is n by the value dimension. The square root of d is not decoration. Dot products of random d dimensional vectors have standard deviation around the square root of d, and softmax of large inputs saturates to a one hot, killing gradients and nuance. Dividing keeps the scores order one at any width.

The page computes a three token example with d equal to two, and every number is live, so check them with a pencil. The upshot for the third token's query: the output vector is fifty seven point six percent token three's value, twenty eight point four percent token two's, and fourteen percent token one's. The query chose its own content and token two's. In a real model this happens for every position, every head, every layer, with d equal to one hundred twenty eight instead of two.

One attention pattern per layer is too coarse. A token may simultaneously need its syntactic subject, the previous mention of the same entity, and the delimiter that opened its bracket. Multi head attention runs h independent attentions in parallel on h learned low dimensional projections. A model width of four thousand ninety six might be thirty two heads of one hundred twenty eight dimensions each. Each head learns its own notion of relevance; induction heads, positional heads, and syntax heads are all well documented. The outputs concatenate and project back. Flops stay the same as one full width head. Expressivity does not.

At serving time, heads have a price. Every key and value head is cached for every token, and since decode is bandwidth bound, reading all those cached heads is the bottleneck. So the variants shrink K and V while keeping all the query heads. Take thirty two query heads. Multi head attention, M H A, has thirty two K V heads, the one x baseline. Grouped query attention, G Q A, uses eight K V heads with groups of four query heads sharing each one: a quarter of the cache, with negligible quality cost. Llama two, Llama three and Mistral use it. Multi query attention, M Q A, uses a single K V head: one thirty second of the cache, a small but real quality cost, and it needs up training. And multi head latent attention, M L A, from DeepSeek V two, caches only one shared latent vector of about five hundred twelve dimensions per token and decompresses the per head keys and values on the fly inside the kernel. Roughly one fourteenth of the cache, and essentially no quality cost, because the latent is trained, and the extra flops are free in a bandwidth bound decode. The page's head sharing animation shows pulses travelling from cached K V at the bottom up to the query heads that read them. Fewer boxes on the bottom row means fewer bytes streamed from H B M per token, which means faster decode and more concurrent users.

Positions. Attention is permutation invariant, so position must be injected. The original transformer added sinusoidal position vectors to the embeddings. G P T two learned one vector per absolute position. Modern models use rotary position embedding, rope. Split each query and key into d over two pairs of two dimensions, and rotate pair number p of the vector at position m by the angle m times theta sub p, where theta sub p equals ten thousand to the power of negative two p over d. Each pair gets its own frequency. Fast spinning pairs resolve nearby order; slow ones encode long range position.

The magic is in the dot product. Rotations compose. A query rotated by m theta, dotted with a key rotated by n theta, depends only on the difference, m minus n, times theta. Attention scores become a function of relative position, "three tokens back," not absolute index, which is what language actually needs, and no vector is ever added to the residual stream. The interactive on the page lets you slide the query position and the key position; move both by the same amount and the vectors spin, but the angle between them and the score do not move. Only the difference matters. Context extension tricks like N T K scaling and YaRN work by stretching the theta frequencies so a model trained at eight thousand positions can be served at one hundred twenty eight thousand without the fast pairs aliasing.

Now the n squared wall. The score matrix is n by n per head. Computing it costs n squared times d flops, which is tolerable, GPUs love matmuls. Materializing it in high bandwidth memory is what killed long context. Write n squared scores. Read them back for softmax. Write n squared weights. Read them back to multiply by V. Four n squared sized H B M round trips, on hardware where H B M traffic, not flops, is the budget. At thirty two thousand tokens, one layer's attention matrices are tens of gigabytes in flight, more than the whole GPU. Use the calculator on the page: at thirty two K tokens, one head's score matrix in F P sixteen is thirty two thousand squared times two bytes, about two gigabytes, and thirty two heads make that sixty four gigabytes for a single layer.

FlashAttention computes exact attention without ever materializing the n by n matrix, by being I O aware: it counts H B M reads and writes, not flops. The kernel tiles Q into row blocks and K and V into column blocks sized to fit in on chip S R A M, which is hundreds of kilobytes with about twenty times H B M's bandwidth. For each Q block it streams K V blocks through S R A M, computing partial scores and accumulating output. One pass, and nothing n squared ever leaves the chip.

The obstacle is softmax. Its denominator needs all the scores of a row before any weight is final. The fix is the online softmax, the same trick the math chapter ended on, now done incrementally. Keep a running maximum m and a running denominator l per row. For each new tile of scores, compute the new maximum. Rescale the old denominator and the old accumulated output by e to the power of old max minus new max. Add the new tile's exponentials to the denominator, and the new tile's exponentials times its values to the output. At the end divide the output by l. It is algebraically identical to the full softmax, but computable tile by tile. The animation on the page shows the n by n matrix that is never stored, with only the highlighted tile living in S R A M, causal masking skipping half the tiles entirely, and the running statistics for the current query block updating live. Watch m jump and l and O get rescaled when a tile contains a new maximum. The H B M counters show why this wins: traffic scales with n times d, not n squared. At thirty two K tokens the page contrasts about eight point six gigabytes of naive traffic with about thirty three megabytes for flash.

The versions since are about mapping this loop onto each GPU generation. FlashAttention two reordered the loops and the work partitioning so each thread block owns a query block, giving parallelism over the sequence, better occupancy, and fewer non matmul operations, about two times over the first version. FlashAttention three exploits Hopper: warp specialization, with producer warps driving asynchronous T M A memory copies while consumer warps run the W G M M A tensor core instructions, overlapping softmax with matmuls, plus F P eight support, for about one and a half to two times over F A two on an H one hundred. FlashAttention four re schedules the whole thing for Blackwell's tcgen zero five tensor cores and tensor memory. The lesson generalizes beyond attention: restructure the algorithm so its working set lives in fast memory, and recompute rather than round trip. That is the founding idea of every fused kernel in the kernels chapter.

Long context, beyond one GPU and below n squared. Ring attention scales exact attention across devices. Shard the sequence. Every device keeps its own query shard, and the K V shards circulate around a ring. Each hop, a device computes one query block against one K V block, merging with online softmax, which composes across devices exactly as it composes across tiles, while simultaneously sending its current K V shard onward. Communication hides behind compute, and after P minus one hops every pair has met. Context then scales linearly with device count. The page's animation shows four devices and a coverage grid filling one diagonal per hop.

Sparse attention attacks n squared itself. M Inference observes that long context prefill attention is dominated by a few recurring patterns per head, A shapes, vertical slash bands, block sparse blobs, classifies each head offline, and computes only the pattern. Up to about ten times faster prefill at a million tokens on existing models, with no retraining. Native sparse attention, N S A from DeepSeek, instead trains the model sparse: each query reads compressed block summaries, a selected set of fine blocks, and a sliding window, with hardware aligned block sizes, so the sparsity is learned end to end. Sliding window attention, as in Mistral, is the degenerate but effective case: attend only to the last w tokens; stacked layers still propagate information w tokens per layer, like a convolutional network's growing receptive field.

One more twist from serving. The K V cache is paged, so keys and values are not even contiguous in memory. Kernels must gather blocks through a block table. FlashInfer is the library built for this regime: paged and ragged K V layouts, prefill, decode, and append variants, shared prefix batch kernels, and just in time tuned schedules, used inside v L L M and S G Lang. During decode there is no parallelism over the query length, because there is one token, so these kernels split work across the K V length instead, in the FlashDecoding style, and merge the partial results with, once again, the online softmax. One idea at four scales: the tile, the thread block, the device ring, and the serving batch.

Interview questions. Why scale by the square root of d? Saturation of softmax at large magnitude. Why is FlashAttention faster if it does the same or more flops? Because attention is bound by H B M traffic, not flops, and tiling plus online softmax removes the n squared round trips. What does G Q A give up versus M H A? Almost nothing in quality, a four times smaller cache for thirty two query heads and eight K V heads. Why does M L A not hurt quality? The latent is learned, and decompressing is free in a bandwidth bound decode. And how does rope encode relative position? Rotations compose, so the dot product depends only on the position difference. A common misconception: people think FlashAttention is an approximation. It is exact. Every number equals standard attention up to floating point rounding.

One more development belongs here, because it is where sparse attention is heading. The production answer to n squared in twenty twenty five and twenty twenty six was a learned indexer, in the style of DeepSeek sparse attention, that scores every past token cheaply and lets each query attend only to its top k. The indexer then became the bottleneck, because scoring every key is still linear per query, and at ten million tokens linear is a great deal of work. Latent sparse attention, from Prefrontal AI, attacks exactly that step. Keys are projected into a learned latent space and clustered into buckets, each with a centroid. A query scores only the centroids, opens the top buckets, and reads the keys inside them, plus two fixed companions, the attention sink at the start of the sequence and a local sliding window of recent tokens. The attention kernel itself is unchanged. Latent sparse attention only decides which keys are read, which is why it can ship as a plugin to S G lang rather than as a new kernel to tune for every G P U.

There are two ways to get the index. The distilled variant retrofits a pretrained model by distilling its own indexer into the latent clustering, with a flat search, a two level tree search, or a training free version that uses a principal components map. The reported numbers are striking. On G L M five point three Flash at ten million tokens, one attention layer runs about twenty three times faster in prefill and about four and a half times faster in decode than the model's own sparse attention. On Qwen three point eight twenty seven B it is seventy two times faster in prefill and forty two times faster in decode than full attention, while ruler accuracy at four thousand and thirty two thousand tokens stays around ninety seven percent. The native variant trains the model from scratch with the mechanism in place, on the next token loss alone, matches full attention accuracy, and trains about one point six times faster per layer at one hundred twenty eight thousand tokens. Open the latent sparse attention bucket animation on the page, drag the bucket and top k sliders, and watch the keys read counter against the two hundred keys full attention would touch.

The second development is about hybrids, and it sharpens the whole chapter. A study titled What Attention Recalls and Recurrence Controls in Hybrid Language Models ablated state at inference time in models such as Qwen three point five twenty seven B and found a clean split. Exact retrieval of specific items depends on the attention K V cache. With only the K V cache intact, retrieval survives at sixty four to ninety eight percent of full accuracy. With only the recurrent state, it collapses to zero. The recurrent state instead carries output language, style, and persona. The few full attention layers are the model's address book, and the recurrent layers are its disposition. Related work even transfers one model's recurrent state into another frozen hybrid through a small correction, precisely because that state holds transferable context rather than exact indices.

That is the seam a twenty twenty six paper called Crystallized Attention, Fixed State Carriers and Exact Index Correction for the Full Attention Heads of a Twenty Seven B Hybrid Language Model, appears to work at. Only its title was available when this chapter was written, so treat what follows as inference. The title suggests giving the full attention heads a fixed size state, the constant memory property recurrent layers already have, while adding an exact index correction so the precise lookups that only true attention provides are preserved. If that reading holds, it is an attempt at constant memory heads without the recall cliff. Check the paper itself before you quote it, and compare it against the mixer table on the page, which lines up full attention, sliding windows, indexers, latent sparse attention, recurrent states, and these crystallized heads by memory per token, index cost, exact recall, and training required.

One more interactive lives at the end of the long context section, after a figure in Alisa Liu's Book of LLMs that reproduces the Longformer drawing of attention patterns. It draws the attention matrix as a grid, queries down the side and keys across the top, and lets you switch between full attention, a sliding window, a dilated window, global tokens plus a window, the causal mask a decoder really computes, block sparse selection in the style of DeepSeek sparse attention, and the sink plus window shape that streaming models and latent sparse attention use. Drag the sequence length up and watch the filled fraction fall for every pattern except full attention, then compare the two memory numbers: the keys each query reads, and the cache that must actually stay resident. A window lets the cache be a ring buffer; a block sparse index reads few keys but needs the whole cache in memory because any block might be chosen. That distinction is the whole argument behind the hybrid ratios in the architectures chapter.
