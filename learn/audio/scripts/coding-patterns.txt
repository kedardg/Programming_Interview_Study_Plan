Here is the secret that separates people who grind five hundred problems from people who walk into interviews calm. The Blind seventy five is not seventy five problems. It is about a dozen moves, each one wearing several costumes. Once you can name the move, a problem you have never seen turns into one you have solved before with different variable names. This episode is a tour of those moves, in the order the Coding Patterns chapter presents them, with one problem walked out loud for each.

First the protocol, because interviewers score process as much as answers. The study plan gives you a forty five minute cap, and the chapter compresses its method into six phases. Understand, three to five minutes: restate the problem, ask about input size, duplicates, empty input, and sortedness, then write one tiny example and one edge case. Match, two to three minutes: name the candidate pattern, and always say the brute force and its complexity first, because it is your safety net. Plan, five to eight minutes: pseudocode, and state the invariant your loop maintains. Implement, twelve to eighteen minutes: signature, skeleton, body, narrating decisions rather than keystrokes. Review, three to five minutes: trace your example by hand and check off by ones, empty input, single element, and negatives. Evaluate, two minutes: time, space, and the trade you would make with more time. If you are stuck at the match phase for more than five minutes, finish the forty five minutes anyway, then watch the matching Aditya Verma tutorial and re-solve the next day. Being stuck is data about which pattern you have not internalized yet.

Family one: arrays and hashing. The move is to trade memory for a lookup, so that have I seen this becomes an order one check. Take Two Sum, problem number one. Keep a hash map from value to index. For each number, check whether target minus the number is already in the map before inserting the current number. With two, seven, eleven, fifteen and a target of nine: at two we look for seven, not there, store two. At seven we look for two, found at index zero, done. One pass, big O of n time and space. The same move powers Contains Duplicate, Group Anagrams with a sorted string as the key, and Longest Consecutive Sequence, where you only count from numbers whose predecessor is not in the set. The second move here is running state. Best Time to Buy and Sell Stock tracks the minimum so far, and Maximum Subarray is Kadane's algorithm: current is the max of the element alone or the element plus current, best is the max of best and current. In words, restart the subarray whenever the running sum would only hurt the next element.

Family two: two pointers and sliding window. Two pointers needs sorted input or input you can sort. Container With Most Water always moves the shorter wall inward, because moving the taller one can never help. Three Sum fixes one element and two pointers the rest, skipping duplicates. The sliding window is the version for contiguous substrings with a constraint. Walk through Longest Substring Without Repeating Characters, problem fifty. Keep a map from character to the index where you last saw it. The right edge advances one character per step; when the new character already sits inside the window, the left edge jumps just past its previous position, a single lookup rather than a scan. On a b c a b b, the second a sends left to index one, the second b sends it to index two, and the best window is a b c, length three. Big O of n, because each edge only moves right. The same shape solves Longest Repeating Character Replacement, where the window is valid if its length minus the top frequency is at most k, and Minimum Window Substring, where you expand until covered and shrink while still covered.

Family three: binary search. Find a monotonic quantity and halve the range on it. Find Minimum in Rotated Sorted Array, problem seven: compare the middle element with the rightmost one. If the middle is larger, the drop is to the right, so low jumps past mid; otherwise the minimum is mid or to its left, so high comes down to mid. On four, five, six, seven, zero, one, two, mid is seven, larger than two, low moves past it; then mid is one, not larger than two, high comes to mid, and one more step lands on zero. Big O of log n. Search in Rotated Sorted Array notices that one half is always sorted and tests whether the target lies inside it. And remember the bigger move, binary search on the answer, whenever checking a candidate is cheaper than computing the answer directly.

Family four: stacks and intervals. A stack holds the most recent unresolved thing: Valid Parentheses pushes openers and each closer must match a pop. Intervals are sort plus sweep. Merge Intervals, problem thirty six: sort by start, and if the next interval starts at or before the current merged interval's end, stretch it; otherwise close it and start a new one. With one to three, two to six, eight to ten, the first two become one to six and the third stands alone. Big O of n log n for the sort. Insert Interval is the same sweep in three parts, Non overlapping Intervals sorts by end and greedily keeps the earliest ending interval, and Meeting Rooms Two moves to a heap of end times.

Family five: linked lists. Two moves, the dummy head and fast and slow pointers. Reverse Linked List is save next, flip the pointer, advance. Linked List Cycle is Floyd's algorithm: slow moves one, fast moves two, and they meet if and only if there is a cycle. Remove Nth Node From End sends one pointer ahead by n from a dummy so the lagging pointer stops right before the target. Reorder List combines everything: find the middle, reverse the second half, interleave.

Family six: trees, binary search trees, and tries. Decide first whether information flows up from the children or down from the parent. Maximum Depth flows up, one plus the max of the children. Maximum Path Sum flows up with a global best: return the best single arm to the parent while updating the global with both arms joined. Validate Binary Search Tree flows down: pass low and high bounds, and never compare only with the parent, because a grandchild can satisfy its parent and still violate the grandparent. Level Order Traversal is breadth first search, processing the queue's current length per level. Lowest Common Ancestor of a BST is a walk: left while both values are smaller, right while both are larger, and the split point is the answer. Tries are nested dictionaries with an end marker, and Word Search Two walks the grid and the trie together, pruning dead prefixes, which is the difference between timing out and passing.

Family seven: heaps, for repeatedly needing the extreme of a changing set. Find Median from Data Stream, problem seventy five: a max heap for the lower half and a min heap for the upper half. Each new number lands in the lower heap, its maximum is handed to the upper heap, then sizes are rebalanced to differ by at most one. The two tops always straddle the median. Big O of log n per insert, order one per median. Merge K Sorted Lists keeps a heap of the current heads, big O of n log k. In Python, heapq is a min heap, so push the negative for a max heap.

Family eight: graphs. Number of Islands is flood fill, sinking each island as you discover it. Clone Graph uses a map from old node to new node that doubles as the visited set. The star is Kahn's algorithm for Course Schedule, problem twenty eight. Compute each course's in degree, the number of unfinished prerequisites. Queue every node with in degree zero. Pop one, decrement each dependent, and enqueue any that reach zero. If the queue runs dry while nodes remain unprocessed, the leftovers are in a cycle, and that is your detection. Alien Dictionary is the same algorithm with edges from the first differing character of adjacent words. Graph Valid Tree and Connected Components use union find: a tree is n minus one edges with no union failing, and the component count is n minus the successful unions.

Family nine: dynamic programming, the one everyone fears and the one with the clearest recipe. Define the state, write the recurrence, set the base cases, choose the fill order, read off the answer. Coin Change, problem seventeen: dp of amount a is one plus the minimum of dp of a minus each coin, with dp of zero equal to zero, filling amounts upward so every cell is computed after the cells it depends on. With coins one, three, and four and amount six, the answer is two, three plus three, while greedy takes four plus one plus one and gets three. That one example is the whole reason DP exists where greedy fails. Big O of amount times coins. Climbing Stairs is Fibonacci with two variables, House Robber keeps a take and skip pair, Word Break asks whether any earlier cut is reachable with the remainder in the dictionary, and Longest Common Subsequence is two dimensional: diagonal plus one on a match, else the max of up and left.

Family ten: bit manipulation, a small set of identities. n and n minus one clears the lowest set bit. The bit count of i equals the count of i shifted right plus its lowest bit, a DP in disguise. XOR of all indices and values exposes the missing number. Sum of two integers is XOR for the sum without carry and the AND shifted left for the carry, looped until the carry is zero.

Family eleven: backtracking and matrix tricks. Backtracking is depth first search over choices with undo: Word Search marks a cell, explores, and unmarks. Matrix problems are bookkeeping: Rotate Image is transpose then reverse each row, Spiral Matrix is four shrinking bounds, Set Matrix Zeroes uses row zero and column zero as flags.

Now the decision walk, as a checklist for the match phase. Sorted, or can sorting help? Two pointers or binary search. A contiguous subarray or substring with a constraint? Sliding window or prefix sums. Have I seen this, or grouping? Hash map or set. Count the ways, or min or max over choices with overlapping subproblems? Dynamic programming, write the recipe. Dependencies, components, or a grid? A graph: topological sort, union find, flood fill, breadth first search for shortest unweighted paths. The extreme of a changing set? Heap. Most recent matching item or next greater? Stack. Enumerate configurations with pruning? Backtracking. Linked structure? Dummy head and fast slow. A tree? Decide up or down, and reserve breadth first search for level problems. If nothing fits, say the brute force aloud and hunt for the monotonic quantity. It is usually hiding there.

A few misconceptions worth killing. Memorizing solutions is not the goal; the interviewer will perturb the problem, and only the pattern survives. Silence is not thoughtful, it is invisible; talk while you code, narrating decisions and invariants. Finishing the code is not finishing the problem; trace your example, then try the empty input, a single element, all equal values, and negatives. Know your Python costs: popping from the front of a list is linear, string concatenation in a loop is quadratic, and recursion depth defaults to a thousand. And the complexity target comes from the input size: twenty elements allows exponential backtracking, a thousand allows quadratic, a million demands n log n or linear, a billion means logarithmic or math.
