Quantization, Sparsity & Numerics

Every tensor in a model is a pile of numbers in some binary format, and the format decides memory, bandwidth, and silicon cost. This chapter covers how floating-point formats actually work, the math of quantization, the algorithms used in practice (GPTQ, AWQ, FP8, NVFP4), KV-cache quantization, quantization-aware training, and structured sparsity. It is the numerics counterpart of Step 13 in the study plan.

1. Number formats: where the bits go

A floating-point number spends its bits on three jobs: one sign bit, some exponent bits, and some mantissa (fraction) bits. The split is the whole personality of a format:

  • Exponent bits buy range. With E exponent bits you get roughly 2E binades (powers of two). FP32 and BF16 both have 8 exponent bits, so both reach ~3.4×1038; FP16 has only 5, so it tops out at 65,504 and underflows below ~6×10-8.
  • Mantissa bits buy precision. M mantissa bits give you 2M evenly spaced values inside each binade — about M+1 significant bits, or (M+1)×0.30 decimal digits.

The decoded value of a normal float is:

value = (-1)^sign × 2^(exponent - bias) × (1 + mantissa / 2^M),  bias = 2^(E-1) - 1

When the exponent field is all zeros the number is subnormal: the implicit leading 1 disappears and the format trades precision for a gentle fade to zero. When it is all ones, the value is ±Inf or NaN — except FP8-E4M3, which is so starved for bits that it spends the all-ones pattern on real values and keeps only one NaN encoding, giving up Inf entirely.

Why BF16 won training: FP16's 5-bit exponent underflows gradients and overflows loss scales, demanding fiddly loss-scaling tricks. BF16 keeps FP32's full 8-bit exponent — same range, no loss scaling — and gives up mantissa instead, which deep learning barely notices because gradient noise dwarfs rounding error. TF32 is the tensor-core compromise inside Ampere+: FP32 range, 10-bit mantissa, used silently when you multiply FP32 matrices. The 2026-era training recipe is BF16 master weights with FP8 (and now FP4) matmuls where they prove stable.

2. The math of quantization

Quantization maps real values to a small grid of integers plus shared metadata. The two basic schemes:

# symmetric (absmax): grid centered on zero scale = max(|x|) / 127 # for INT8 q = round(x / scale) # integer code in [-127, 127] x̂ = q × scale # dequantized # asymmetric (affine): grid shifted to fit [min, max] scale = (max - min) / 255; zero_point = round(-min / scale) q = clamp(round(x / scale) + zero_point, 0, 255); x̂ = (q - zero_point) × scale

Worked example — quantize [0.3, −1.2, 2.4, 0.05] to symmetric INT8:

absmax = 2.4, so scale = 2.4/127 ≈ 0.0189. The largest value is exact; everything else lands on the nearest grid point.

The catch: one outlier sets the scale for everyone. If a single weight is 50 while the rest live in [−1, 1], the grid step becomes 50/127 ≈ 0.39 and every normal weight collapses onto two or three codes. The fix is granularity — give smaller groups their own scale:

  • Per-tensor: one scale for the whole matrix. Cheapest, most fragile.
  • Per-channel: one scale per output row. Standard for weights.
  • Per-group: one scale per contiguous group of 32–128 elements along a row. The default for 4-bit LLM weights (g=128 in GPTQ/AWQ).

Switch to per-group scales: only the outlier's own group pays. This single picture explains why every modern format carries block-level scales.

3. Weight-only post-training quantization: GPTQ and AWQ

For inference, the first 4× is nearly free. Decode is bandwidth-bound (inference chapter): each token requires streaming every weight byte from HBM. Llama-70B in FP16 is ~140 GB; in 4-bit it is ~35 GB plus ~3% for group scales. Same FLOPs, one quarter the bytes — up to ~4× faster decode at small batch, and the model now fits on half the GPUs. This is W4A16: weights stored in INT4, activations kept in FP16, weights dequantized on the fly in the GEMM kernel (Marlin, ExLlama) so tensor cores still do FP16 math.

Rounding each weight to the nearest grid point is not optimal — what matters is the layer output, not each weight. The two algorithms the ecosystem settled on:

  • GPTQ quantizes a weight matrix column by column, and after fixing each column it updates the remaining columns to compensate, using second-order information (the Hessian of the layer's reconstruction error, built from calibration activations). Intuition: if rounding weight wi up added +ε to the output, nudge the not-yet-quantized weights that multiply correlated inputs down to cancel it. The result is a 3–4 bit model whose layer outputs track the FP16 layer closely — far better than naive rounding at the same bit-width.
  • AWQ observes that a small fraction of weight channels matter far more than others — the ones multiplied by large activations. Rather than mixed precision, it rescales: divide salient activation channels by s, multiply the corresponding weight channels by s (mathematically a no-op), so the important weights occupy more of the quantization grid before rounding. No backprop, no Hessian; robust across domains, and the usual default for 4-bit serving.

4. Quantizing activations too: FP8 and micro-block FP4

Weight-only quantization stops helping once batch grows and the GEMMs become compute-bound — then you want cheaper math, which means quantizing activations so the tensor cores can run at INT8/FP8/FP4 rates (each halving of operand width roughly doubles peak FLOPs). Activations are harder than weights: they are produced at runtime and contain systematic outlier channels.

  • FP8 (Hopper/Ada onward): E4M3 for forward tensors, E5M2 where range matters (historically gradients). Each tensor carries an FP32 scale chosen from its recent amax history (delayed scaling) so the kernel doesn't have to scan the tensor before using it. FP8 inference with per-tensor scales is now routine for serving (DeepSeek-V3 even trained in FP8).
  • SmoothQuant: activations have outlier channels, weights don't. So migrate the difficulty: divide activation channel c by sc, multiply weight column c by sc. Activations get smoother, weights absorb the roughness they can afford, and both quantize to 8 bits cleanly.
  • NVFP4 / MXFP4 (Blackwell): at 4 bits, per-tensor scaling is hopeless, so the scale moves into the format itself. MXFP4: every 32 elements share a power-of-two E8M0 scale. NVFP4: every 16 elements share an FP8-E4M3 scale plus one FP32 scale per tensor — finer blocks and a real-valued scale, which is why NVFP4 holds accuracy where plain MXFP4 struggles. The hardware reads blocks and scales together; the animation below shows the idea.

Animation: micro-block scaling

32 values, blocks of 8 (stand-ins for NVFP4's 16 / MXFP4's 32). The sweep computes each block's own scale (bar above the block) and quantizes its members to FP4's 15 grid points. A big value in block 2 no longer costs blocks 1, 3, 4 any precision — outlier damage is contained to one block. This is the per-group idea from §2 baked into silicon.

5. Quantizing the KV cache

At long context the KV cache, not the weights, dominates memory — and it is bandwidth read every decode step, so quantizing it buys both capacity and speed. The wrinkle (KIVI's observation): keys and values fail differently. Key tensors have a few channels with persistently large magnitude across all tokens, so keys want per-channel scales; value tensors have no outlier channels but are consumed token-by-token through the attention weights, so values quantize best per-token. With that split, 2-bit KV with a small FP16 residual window works; FP8 KV cache is near-lossless and is now a standard serving flag. 6. Training with quantization: QAT, STE, QLoRA

Quantization-aware training inserts fake quantization into the forward pass: weights and activations are rounded to the target grid (then dequantized) so the network experiences quantization noise while it still has gradients to adapt with. The round function has zero gradient almost everywhere, so the backward pass uses the straight-through estimator (STE): pretend round() is the identity and pass the gradient through unchanged. Crude, but it works — the network learns weights that sit comfortably on the grid, recovering most of the gap that post-training quantization leaves at 4 bits and below. Axolotl exposes this as qat: config for int8/int4/FP8/NVFP4 (training chapter).

QLoRA makes fine-tuning cheap instead: freeze the base model in 4-bit NF4 — a 16-point grid placed at the quantiles of a standard normal, which is information-theoretically optimal for normally distributed weights — and train small FP16 LoRA adapters on top. Double quantization quantizes the per-block scales themselves (FP32 → FP8 with a second-level scale), shaving another ~0.37 bits/parameter. Gradients flow through the frozen 4-bit weights into the adapters only, so a 70B fine-tune fits where only a 7B used to.

7. Sparsity

Quantization shrinks every number; sparsity deletes some entirely. The catch is that hardware hates irregularity: a weight matrix with random zeros still has to be fetched and multiplied unless the pattern is structured enough for silicon to exploit. That is why 2:4 structured sparsity (Ampere onward) is the only sparsity with first-class hardware support: in every group of 4 weights, exactly 2 must be zero. The GPU stores the 2 survivors plus 2-bit indices (half the memory) and the sparse tensor cores skip the zeros for up to 2× math throughput.

Animation: 2:4 structured pruning

A weight row in groups of 4. Step 1: magnitude pruning zeroes the 2 smallest of each group (greyed). Step 2: compression keeps only survivors plus 2-bit position indices — half the storage, and sparse tensor cores skip the zeros. Unstructured pruning can remove 90%+ of weights at similar accuracy, but without a pattern the hardware can't skip anything, so it rarely pays on GPUs.
