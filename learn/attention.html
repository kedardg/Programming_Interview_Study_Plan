Attention, FlashAttention & Long Context

The mechanism itself, computed by hand; multi-head and its cache-saving variants; RoPE; and the kernel that made long context affordable — FlashAttention's tiling and online softmax, animated tile by tile. This is the deep dive behind Step 12 of the study plan.

1. Attention from first principles

Attention is a soft dictionary lookup. Each position emits a query ("what am I looking for?"), and offers a key ("what do I contain, as an address?") and a value ("what do I contribute, as content?"). A query is compared against every key by dot product — the natural "how aligned are we?" measure from the math chapter — the comparisons become weights via softmax, and the output is the weight-blended average of the values. Nothing is retrieved exactly; everything is retrieved a little, in proportion to relevance.

Attention(Q, K, V) = softmax( QKᵀ / √d_k ) V

shapes: Q: n×d_k K: n×d_k V: n×d_v QKᵀ: n×n output: n×d_v
(n = sequence length; d_k = d_v = head dim, typically 64–128)

The √dk matters: dot products of random d-dimensional vectors have standard deviation ~√d, and softmax of large-magnitude inputs saturates to a one-hot — killing gradients and nuance. Dividing by √dk keeps scores O(1) at any width.

Worked example: 3 tokens, d = 2, by hand

Read it bottom-up: the output vector is 57.6% token 3's value, 28.4% token 2's, 14.0% token 1's — the query "chose" its own and token 2's content. In a real model this happens for every position, every head, every layer, with d = 128 instead of 2.

2. Multi-head attention and the KV-saving variants

One attention pattern per layer is too coarse: a token may simultaneously need its syntactic subject, the previous mention of the same entity, and the delimiter opening its bracket. Multi-head attention runs h independent attentions in parallel on h learned low-dimensional projections (d_model = h × d_head, e.g. 4096 = 32 × 128), letting each head learn its own notion of relevance — induction heads, positional heads, syntax heads are all well-documented. The outputs concatenate and project back. FLOPs stay the same as one full-width head; expressivity doesn't.

At serving time, heads have a price: every K/V head is cached for every token (the KV cache formula). Since decode is bandwidth-bound, reading all those cached heads is the bottleneck — so the variants below shrink K/V while keeping all the query heads:

3. Positional encoding: RoPE

Attention is permutation-invariant, so position must be injected. The original transformer added sinusoidal position vectors to embeddings; GPT-2 learned one vector per absolute position. Modern models use Rotary Position Embedding (RoPE): split each query and key into d/2 two-dimensional pairs and rotate pair p of the vector at position m by angle m·θp, where θp = 10000−2p/d gives each pair its own frequency — fast-spinning pairs resolve nearby order, slow ones encode long-range position.

The magic is in the dot product. Rotations compose: a query rotated by m·θ dotted with a key rotated by n·θ depends only on the difference (m−n)·θ. Attention scores become a function of relative position — "3 tokens back" — not absolute index, which is what language actually needs, and no vector is ever added to the residual stream.

Interactive: rotation encodes relative position

One frequency pair, one q (blue) and one k (green), each rotated by its position × θ. Slide both positions by the same amount — the vectors spin, but the angle between them and the score q·k do not move. Only m−n matters. Context extension tricks (NTK scaling, YaRN) work by stretching the θ frequencies so a model trained at 8K positions can be served at 128K without the fast pairs aliasing.

4. The n² wall

The score matrix QKᵀ is n×n per head. Computing it is O(n²d) FLOPs — tolerable, GPUs love matmuls — but materializing it in HBM is what killed long context: write n² scores, read them back for softmax, write n² weights, read them back to multiply by V. Four n²-sized HBM round trips, on hardware where HBM traffic, not FLOPs, is the budget (the roofline model).

At 32K tokens one layer's attention matrices are tens of gigabytes in flight — more than the whole GPU. FlashAttention's answer: never write them at all. Its HBM footprint beyond Q, K, V, O is just the per-row statistics, linear in n.

5. FlashAttention: tiling + online softmax

FlashAttention computes exact attention without ever materializing the n×n matrix, by being IO-aware: it counts HBM reads and writes, not FLOPs. The kernel tiles Q into row blocks and K/V into column blocks sized to fit in on-chip SRAM (~hundreds of KB, ~20× HBM's bandwidth — see the memory hierarchy). For each Q block it streams K/V blocks through SRAM, computing partial scores and accumulating output — one pass, nothing n² ever leaves the chip.

The obstacle is softmax: its denominator needs all scores of a row before any weight is final. The fix is the online softmax (from the study plan's Step 9 kernel exercises — this is why that exercise exists): keep a running maximum m and running denominator l per row, and whenever a new tile raises the maximum, rescale what you've accumulated so far by em_old − m_new. Algebraically identical to the full softmax, but computable tile by tile:

for each K/V tile j:
s = Q_i K_jᵀ/√d # tile of scores, lives only in SRAM
m_new = max(m, rowmax(s))
l = l·e^(m−m_new) + rowsum(e^(s−m_new))
O = O·e^(m−m_new) + e^(s−m_new)·V_j
m = m_new
output: O / l # exact softmax(QKᵀ/√d)V

Animation: the kernel, tile by tile

Left: the n×n score matrix that is never stored — only the highlighted tile exists, in SRAM. Causal masking skips the greyed tiles entirely (half the work). Right: the running statistics for the current query block — watch m jump and l and O get rescaled by em−m_new when a tile contains a new maximum. The HBM counters show why this wins: traffic scales with n·d, not n².

The versions since are about mapping this loop onto each GPU generation: FlashAttention-2 reordered the loops and work partitioning so each thread block owns a Q block (parallelism over sequence, better occupancy, fewer non-matmul ops) — ~2× over FA-1. FlashAttention-3 exploits Hopper: warp specialization with producer warps driving TMA (async memory copies) while consumer warps run WGMMA tensor-core ops, overlapping softmax with matmuls, plus FP8 support — ~1.5–2× over FA-2 on H100. FlashAttention-4 re-schedules for Blackwell's tcgen05 tensor cores and tensor memory. The lesson generalizes beyond attention: restructure the algorithm so its working set lives in fast memory, and recompute rather than round-trip — the founding idea of every fused kernel in the kernels chapter.

6. Long context: beyond one GPU, below n²

Ring Attention scales exact attention across devices: shard the sequence, let every device keep its Q shard, and circulate K/V shards around a ring. Each hop, a device computes one Q-block × KV-block interaction (merging with online softmax, which composes across devices just like across tiles) while simultaneously sending its current KV shard onward — communication hides behind compute, and after P−1 hops every pair has met. Context then scales linearly with device count.

Animation: KV blocks around the ring

Four devices, four sequence shards. Each device's Q stays home (outer label); the colored KV blocks hop clockwise each step. The coverage grid fills one diagonal per hop — after 3 rotations every Qᵢ has seen every KVⱼ, with the n×n work evenly split and no device ever holding more than 1/4 of the KV.

Sparse attention attacks n² itself. MInference observes that long-context prefill attention is dominated by a few recurring patterns per head (A-shapes, vertical-slash bands, block-sparse blobs), classifies each head offline, and computes only the pattern — up to ~10× faster prefill at 1M tokens on existing models, no retraining. Native Sparse Attention (NSA) instead trains the model sparse: each query reads compressed block summaries, a selected set of fine blocks, and a sliding window, with hardware-aligned block sizes — so the sparsity is learned end-to-end rather than guessed post hoc. Sliding-window attention (Mistral) is the degenerate-but-effective case: attend only to the last w tokens; stacked layers still propagate information w tokens per layer, like a CNN's growing receptive field.

7. Attention kernels in serving engines

Serving adds one more twist: the KV cache is paged, so K and V are not even contiguous — kernels must gather blocks through a block table. FlashInfer is the library built for this regime: paged and ragged KV layouts, prefill/decode/append variants, shared-prefix batch kernels, and JIT-tuned schedules, used inside vLLM and SGLang. During decode there is no parallelism over query length (one token), so these kernels split work across the KV length instead (FlashDecoding-style), merging partial results with — once again — the online softmax. One idea, four scales: tile, thread block, device ring, serving batch.
