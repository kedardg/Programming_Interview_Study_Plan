From Markov decision processes to vision-language-action models: the math of learning from reward, why robots make it hard, how imitation learning took over, and how the same PPO/GRPO that aligns LLMs now trains policies that fold laundry. 1. RL foundations: the MDP and the Bellman equation

Supervised learning is told the right answer. Reinforcement learning is only told how well it did, later, and must work out which of its actions deserve the credit. The formal object is the Markov decision process: a tuple (S, A, P, R, γ). At each step the agent observes a state s ∈ S, picks an action a ∈ A, the environment samples the next state from P(s′ | s, a) and emits a reward R(s, a, s′). The discount γ ∈ [0,1) makes an infinite sum finite and encodes a preference for sooner reward. The Markov property — the next state depends only on the current state and action — is what makes everything below tractable, and is exactly what robots violate (Section 4).

The agent's goal is to maximize the return, the discounted sum of future rewards Gt = rt+1 + γ rt+2 + γ² rt+3 + …. Because the future is random, we reason about expectations. The state-value function Vπ(s) = Eπ[Gt | st = s] says how good it is to be in s and then follow policy π; the action-value function Qπ(s, a) says how good it is to take a first and follow π afterwards. Both satisfy a recursive consistency condition, the Bellman equation, which is the whole engine of RL:

Vπ(s) = Σa π(a|s) Σs′ P(s′|s,a) [ R(s,a,s′) + γ Vπ(s′) ] Q*(s,a) = Σs′ P(s′|s,a) [ R(s,a,s′) + γ maxa′ Q*(s′,a′) ] ← Bellman optimality

"The value of now equals the immediate reward plus the discounted value of next." The optimal policy is then greedy: π*(s) = argmaxa Q*(s, a). Everything from tabular Q-learning to PPO to GRPO is a method for estimating these quantities when P is unknown and S is enormous.

Worked example: a 3-state chain

States {A, B, C}, C is terminal. In A or B you can stay (reward 0) or advance (reward −1 for the effort, except B→C which pays +10). γ = 0.9, transitions deterministic. Compute V* by backward induction from the terminal state:

Set ε to 0 early and the agent locks into the first path it finds; raise α and the values jitter — the two classic RL dials.

Three distinctions you must be able to explain

Exploration vs exploitation. A greedy agent repeats the best action it knows; it never learns that an untried action was better. ε-greedy (random action with probability ε), optimistic initialization, entropy bonuses, and curiosity are all ways to pay a short-term cost for information. In the gridworld, the entire difference between finding the short path and settling for a long one is ε.

On-policy vs off-policy. An on-policy method (SARSA, REINFORCE, PPO) evaluates and improves the policy that generated the data, so the data is thrown away after each update. An off-policy method (Q-learning, DQN, SAC) learns about the greedy policy from data generated by any behavior policy — which is what lets it reuse a replay buffer and, in robotics, learn from logged demonstrations. Q-learning's max in the target is exactly what makes it off-policy: it asks "what would the best action have been?" regardless of what was actually taken.

Model-free vs model-based. Model-free methods learn V, Q, or π directly from experience. Model-based methods learn (or are given) P and R and plan in the model — vastly more sample-efficient when the model is good, catastrophic when it is not. Robotics lives on this boundary: physics simulators are models (Section 4), and learned world models (Section 7) are the modern attempt to get sample efficiency without hand-written physics.

2. RL fundamentals: the ladder from bandits to PPO (and the LLM branch to DPO and GRPO)

Section 1 gave you the MDP and one algorithm, Q-learning, dropped in from the sky. This section builds the ladder underneath it. Every modern method — DQN, PPO, SAC, the RLHF of chat models, GRPO for reasoning — is one or two rungs above something in Sutton and Barto's first six chapters, and interviewers love to walk down the ladder: "why does PPO clip?", "why is Q-learning off-policy?", "what is DPO actually optimizing?". If you can climb from a slot machine to the DPO loss without a gap, you own the topic.

Rung 0: bandits — the zero-state problem that RLHF secretly is

Strip the state out of an MDP and you have the multi-armed bandit: k arms, each with an unknown reward distribution; pull one, observe a reward, repeat. There is nothing to plan, only the exploration–exploitation dilemma in its purest form. Three classic answers: ε-greedy pulls the best-looking arm with probability 1−ε and a random arm otherwise (simple, never stops exploring); UCB pulls the arm maximizing Q̂(a) + c·√(ln t / N(a)), an optimism bonus that shrinks as an arm gets sampled (provably near-optimal regret); Thompson sampling keeps a posterior over each arm's mean and pulls the arm that wins a random draw from the posterior (Bayesian, embarrassingly effective). Add an observed context the agent cannot influence and you have the contextual bandit.

Hold onto that last definition, because it is the bridge to language models. In RLHF a prompt arrives (the context), the policy emits a whole response (the action), a reward model scores it once (the terminal reward), and the episode ends. There is no next state the policy's action influences. RLHF with PPO is, formally, a contextual bandit solved with a full-MDP algorithm — which is exactly why GRPO can throw away the critic and why so much of PPO's machinery (GAE over time, value bootstrapping) collapses to trivial cases there. We return to this in the LLM branch below.

Rung 1: Monte Carlo — learn from complete episodes

Back in an MDP, the simplest way to estimate Vπ(s) is to do what the definition says: run episodes, record the return Gt that followed each visit to s, and average. First-visit MC prediction averages the return after the first visit to s in each episode; every-visit averages all of them. Both converge to the true value by the law of large numbers. MC control does the same for Q(s,a) and improves the policy greedily between episodes; because a deterministic greedy policy would never try some actions, it uses an ε-soft policy (every action keeps probability at least ε/|A|) so every state–action pair is visited forever.

Two properties define MC. It is unbiased: the sampled return is the thing you want, no approximation. And it has high variance: a return sums dozens of random rewards and transitions, so each sample is noisy and you need many episodes. It also needs episodes to end — you cannot update until the return is known — which rules it out for continuing tasks and makes it slow when episodes are long. Policy-gradient REINFORCE (Section 3) is Monte Carlo applied to policies, and inherits the same variance problem; everything after it is variance reduction.

Rung 2: temporal-difference learning — bootstrap instead of waiting

TD(0) updates after every step by replacing the unknown return with a one-step estimate: the target is r + γV(s′), using the current value of the next state as a stand-in for the future. The update is V(s) ← V(s) + α[r + γV(s′) − V(s)], and the bracket is the TD error δ. Using your own estimate inside the target is called bootstrapping. It trades the two properties of MC: TD is biased (the target depends on possibly-wrong estimates) but low variance (one reward and one transition per update), learns online from incomplete episodes, and in practice converges faster. n-step returns interpolate — bootstrap after n real rewards — and TD(λ) averages all n-step returns with geometric weights λn−1, implemented incrementally with eligibility traces that keep a decaying memory of recently visited states and apply each TD error to all of them at once. λ=0 is TD(0), λ=1 is MC; GAE in PPO is precisely this interpolation applied to advantages.

For control, the TD idea yields two algorithms that differ by one symbol, and that symbol is the on-policy/off-policy divide from Section 1:

Rung 3: function approximation and the deadly triad

Tables die at a few thousand states; a camera frame is 105 pixels. Replace the table with a parametric function V(s; w) or Q(s,a; w) — linear features, then a neural network — and apply the same TD updates as gradient steps on the squared TD error, treating the target as a constant (a semi-gradient). This is where theory gets nervous. Sutton and Barto's deadly triad: combining bootstrapping (TD targets), off-policy learning (Q-learning's max), and function approximation can diverge — the value estimates grow without bound even on tiny problems. DQN (2015) is all three at once, and its two famous additions are precisely the stabilizers: an experience replay buffer breaks the correlation between consecutive samples so the gradient steps look like supervised learning on an i.i.d. batch, and a target network — a lagged copy of the weights used to compute r + γ max Qtarget — stops the target from chasing the estimate it is computed from. The refinements each fix a named flaw: Double DQN selects the argmax with the online network and evaluates it with the target network to remove maximization bias; dueling networks split Q into V(s) + A(s,a) so states where actions do not matter learn faster; prioritized replay samples transitions with large TD error more often.

Rung 4: from values to policies — and why PPO clips

Value methods need an argmax over actions, hopeless for a 30-dimensional joint vector. Policy methods parametrize π(a|s; θ) directly and climb the expected return with the policy gradient — the derivation and REINFORCE are in Section 3. The ladder from REINFORCE to PPO is three variance-reduction steps and one stability step. Baseline: subtracting any state-dependent b(s) from the return leaves the gradient's expectation unchanged but cuts its variance; the natural baseline is V(s). Advantage: what remains, A(s,a) = Q(s,a) − V(s), "how much better than usual was this action"; estimate it with TD-style targets and you have an actor-critic, the actor being π and the critic V, with GAE(λ) as the n-step interpolation that controls the critic's bias–variance trade. Trust region: a policy gradient step with a large learning rate can change π so much that the data it was computed from no longer describes the policy, and performance collapses. TRPO (Schulman et al., 2015) constrains each update to a KL ball around the old policy — correct but needs second-order optimization. PPO (2017) gets the same effect with a first-order trick: optimize the surrogate rt(θ)·At, where rt = πθ(a|s)/πold(a|s), but clip the ratio to [1−ε, 1+ε] and take the minimum with the unclipped term. The minimum makes the objective pessimistic: once the ratio has moved past the clip boundary in the direction the advantage favors, the gradient is zero and the step cannot keep pushing. That is the whole reason PPO is the default — the same handful of lines stabilize a 2-link arm and a 70B chat model.

Interactive: what PPO's clipped objective actually does

The surrogate L(r) = min(r·A, clip(r, 1−ε, 1+ε)·A) plotted against the probability ratio for a positive advantage (green) and a negative one (red); shaded bands are where the clip is active. Drag the ratio marker: inside the band the gradient is the plain policy gradient; beyond it, in the direction the advantage pushes, the curve goes flat and the gradient vanishes — the policy cannot move further on this sample. In the other direction the unclipped term wins (the min keeps the correction), so bad moves are always undone. Widen ε and watch the flat region retreat: more aggressive updates, less stability.

import torch def gae(rewards, values, dones, gamma=0.99, lam=0.95): """Generalized advantage estimation over one trajectory. values has T+1 entries (bootstrap value for the final state appended). lam=0 -> one-step TD advantage (low variance, biased); lam=1 -> Monte Carlo (unbiased, noisy).""" T = len(rewards) adv = torch.zeros(T) last = 0.0 for t in reversed(range(T)): nonterminal = 1.0 - dones[t] delta = rewards[t] + gamma * values[t + 1] * nonterminal - values[t] # TD error last = delta + gamma * lam * nonterminal * last # eligibility-style recursion adv[t] = last returns = adv + values[:-1] # critic targets return adv, returns def ppo_policy_loss(new_logp, old_logp, adv, eps=0.2): ratio = torch.exp(new_logp - old_logp) # pi_theta / pi_old, computed in log space adv = (adv - adv.mean()) / (adv.std() + 1e-8) # per-batch normalization (variance reduction) unclipped = ratio * adv clipped = torch.clamp(ratio, 1 - eps, 1 + eps) * adv return -torch.min(unclipped, clipped).mean() # pessimistic surrogate; gradient is zero when clipped

The LLM branch: PPO → DPO → GRPO

Now return to the bandit bridge. RLHF with PPO (Ouyang et al., 2022) trains a reward model on human preference pairs, then runs PPO on prompts with the reward model's score as the terminal reward and a KL penalty to a frozen reference model to keep the policy from drifting into reward-hacking gibberish. Four models sit in memory (policy, reference, reward, critic), rollouts are expensive, and the whole apparatus is heavy for what is formally a one-step bandit.

DPO (Rafailov et al., 2023) removes the reward model and the rollouts with one observation. Assume human preferences follow the Bradley–Terry model: the probability that response yw is preferred over yl is σ(r(yw) − r(yl)). The KL-regularized RLHF objective has a closed-form optimal policy: π*(y|x) ∝ πref(y|x)·exp(r(x,y)/β). Invert it and the reward is expressible in terms of the policy itself, r = β·log(π/πref) + const. Substitute that into Bradley–Terry and the unknown reward disappears: you can fit the policy directly on preference pairs with a classification loss:

L_DPO(θ) = −E_(x, y_w, y_l) [ log σ( β·( log π_θ(y_w|x)/π_ref(y_w|x) − log π_θ(y_l|x)/π_ref(y_l|x) ) ) ]

Read it as: raise the log-probability margin of the chosen response over the rejected one, measured relative to the reference, with β setting how far from the reference you are allowed to go (small β = strong KL leash). Only two models (policy and frozen reference), no sampling, off-policy on a fixed dataset — which is also its weakness: it can only reshuffle probability among responses it has seen, it over-optimizes on the pair set, and it cannot discover new behaviors the way on-policy sampling can. The variants are one-line fixes: IPO replaces the log-sigmoid with a squared loss that resists over-optimization; KTO needs only thumbs-up/down labels, not pairs; ORPO folds the preference term into the SFT loss so no reference model is needed; SimPO drops the reference and normalizes by length. GRPO (DeepSeekMath, 2024) goes the other way — back to on-policy sampling, but exploiting the bandit structure: sample G responses per prompt, score them with a verifier or reward model, and use (score − group mean)/group std as the advantage, so no critic is trained; the PPO ratio-and-clip machinery is kept token-wise. The systems consequences of that choice — rollouts dominating, weight sync, reward hacking — are the subject of the RL Systems chapter.

3. Deep RL: from tables to gradients

Tables die at the first camera image. Deep RL replaces the table with a network — but naively plugging a network into Q-learning diverges, because the target r + γ max Q(s′,·) moves every time the weights move, and consecutive samples are correlated. DQN (2015) added two stabilizers that are now everywhere: a replay buffer (sample random minibatches of past transitions to break correlation and reuse data) and a target network (a frozen copy of Q used for the targets, synced every few thousand steps). Double DQN, dueling heads, prioritized replay, and distributional Q (Rainbow) are refinements; the two stabilizers are the idea.

Policy gradients: optimizing the policy directly

Q-learning learns values and derives a policy. Policy-gradient methods parameterize the policy πθ(a|s) directly — essential when actions are continuous (joint torques) and argmax over actions is impossible. We want ∇θ J(θ) where J is the expected return. The trick is the log-derivative identity ∇p = p ∇log p, which turns a gradient of an expectation into an expectation of a gradient we can sample:

J(θ) = Eτ~πθ[ R(τ) ] ∇θ J = ∇θ ∫ pθ(τ) R(τ) dτ = ∫ pθ(τ) ∇θ log pθ(τ) R(τ) dτ = Eτ[ ∇θ log pθ(τ) · R(τ) ] and since the dynamics P(s′|s,a) don't depend on θ, log pθ(τ) = Σt log πθ(at|st) + const: ∇θ J = E[ Σt ∇θ log πθ(at|st) · Gt ] ← REINFORCE (with reward-to-go Gt)

Read it as: increase the log-probability of actions that were followed by high return, decrease those followed by low return, in proportion. It is unbiased and horribly high-variance. Two fixes make it practical. A baseline b(s) subtracted from Gt leaves the gradient unbiased but shrinks variance; the natural baseline is V(s), giving the advantage A(s,a) = Q(s,a) − V(s): "how much better than average was this action?" Learning V with a second network makes it an actor-critic. GAE (generalized advantage estimation) blends one-step TD errors δt = rt + γV(st+1) − V(st) over horizons with a λ-weighted sum, trading bias for variance with one knob.

Animation: the policy gradient as "upweight what worked"

A Gaussian policy over launch angle (mean μ, std σ) fires shots from the left toward the target. Each update samples a batch, scores every shot by −distance, subtracts the batch mean (the baseline), and nudges μ toward above-average shots (thick green) and away from below-average ones (thin red) — literally ∇log π · A. σ shrinks as the policy gets confident. Small batches wobble; large batches converge smoothly: variance is the whole story of policy gradients.

PPO: the default algorithm, in RL and in RLHF

Vanilla policy gradient has a step-size problem: one large update can move the policy into a region where its own data is useless, and recovery is slow. TRPO solved this with a KL-constrained trust region; PPO gets most of the benefit with a clipped surrogate objective that is just a few lines of code:

ratio rt(θ) = πθ(at|st) / πθold(at|st) LCLIP(θ) = Et[ min( rt Ât , clip(rt, 1−ε, 1+ε) Ât ) ] ε ≈ 0.2 total loss = −LCLIP + c1 · (Vθ(st) − Vtarget)² − c2 · H[πθ(·|st)]

The min with the clipped ratio removes the incentive to move the probability ratio beyond [1−ε, 1+ε] in the direction the advantage favors: the objective goes flat there, so the gradient is zero. That lets you take several epochs of minibatch SGD on the same batch of rollouts (sample efficiency) without the policy running away (stability). PPO is the default for continuous control, for Atari, for Dota, and — crucially for this plan — for RLHF: the same clipped objective, with the LLM as the policy, a reward model as R, and a KL penalty to the SFT model (Chapter 11). GRPO is PPO with the critic removed and the baseline replaced by the group mean. Once you have read the code below, you have read the heart of both.

# Minimal PPO update (discrete or continuous actions via `dist`) — the whole algorithm minus rollout plumbing import torch, torch.nn.functional as F def ppo_update(policy, value_fn, opt, batch, clip_eps=0.2, vf_coef=0.5, ent_coef=0.01, epochs=4, mb=64): obs, act, old_logp, ret, adv = batch # tensors collected under pi_old; adv from GAE, ret = adv + V_old adv = (adv - adv.mean()) / (adv.std() + 1e-8) # per-batch advantage normalization: cheap variance reduction n = obs.shape[0] for _ in range(epochs): # several passes over the SAME data is the point of clipping for idx in torch.randperm(n).split(mb): dist = policy(obs[idx]) # e.g. torch.distributions.Normal(mu, sigma) for robot joints logp = dist.log_prob(act[idx]).sum(-1) # sum over action dims (independent Gaussians) ratio = torch.exp(logp - old_logp[idx]) # pi_theta / pi_old, computed in log space surr1 = ratio * adv[idx] surr2 = torch.clamp(ratio, 1 - clip_eps, 1 + clip_eps) * adv[idx] policy_loss = -torch.min(surr1, surr2).mean() # L^CLIP, negated because we minimize value_loss = F.mse_loss(value_fn(obs[idx]).squeeze(-1), ret[idx]) entropy = dist.entropy().sum(-1).mean() # keeps exploring; the c2 term loss = policy_loss + vf_coef * value_loss - ent_coef * entropy opt.zero_grad(); loss.backward() torch.nn.utils.clip_grad_norm_(list(policy.parameters()) + list(value_fn.parameters()), 0.5) opt.step() # Swap in RLHF: obs = prompt+partial response, act = next token, dist = LM softmax, # ret/adv from a reward model on the full completion, plus a KL(pi || pi_sft) penalty in the reward.

Off-policy actor-critics for continuous control

SAC (soft actor-critic) maximizes return plus policy entropy, J = Σ E[r + α H(π(·|s))], with twin Q-networks and a replay buffer. The entropy term keeps exploration alive automatically (α is tuned online), and the off-policy buffer makes it 10–100× more sample-efficient than PPO on real robots, where every sample costs wall-clock time and wear. It is the standard choice when you can run RL on hardware at all. TD3 is its deterministic sibling: twin critics (take the min to fight overestimation), delayed policy updates, and target-policy smoothing noise; simpler, slightly more brittle. DDPG is the ancestor of both and mostly of historical interest.

4. The robotics problem: why the clean MDP breaks

Every assumption above gets stressed on a real robot:

  • Continuous, high-dimensional actions. A 7-DoF arm plus gripper is an 8-vector of joint commands per step; a humanoid is 30–50. Argmax over actions is impossible; policies must be parametric distributions (Gaussian, or now diffusion/flow, Section 5).
  • Partial observability. Cameras don't see occluded objects, forces, or friction; the "state" is a history of observations, which is why policies take image stacks or recurrent/transformer context — and why the Markov property is a fiction we manage with memory.
  • Real time. Control loops run at 10–50 Hz (sometimes 200–1000 Hz at the torque level). A policy that takes 300 ms per decision needs action chunking or asynchronous inference (Section 6) to keep the robot moving smoothly.
  • Expensive, unsafe data. A simulator gives a million steps per hour; a real robot gives thousands, breaks things, and needs a human to reset the scene. Sample efficiency is not academic.
  • No reset. Episodes don't end cleanly; the cup is on the floor now. Reset-free and autonomous-recovery methods are a research area of their own.
  • The sim-to-real gap. A policy trained in simulation meets different friction, latency, lighting, and camera noise in reality. Domain randomization (train across randomized physics and visuals so the real world looks like one more sample) and system identification (fit the simulator's parameters to the real robot) are the two standard answers; both are easier for locomotion than for contact-rich manipulation, which is why manipulation went the imitation route.

Observation and action spaces in practice. A typical LeRobot dataset row carries observation.images.* (one or more RGB cameras), observation.state (joint positions, sometimes velocities), and action — either target joint positions (position control, the common case for cheap arms like the SO-100) or end-effector deltas (Δx, Δy, Δz, Δrotation, gripper). Position targets are easier to learn and safer than torques; end-effector deltas transfer better across robots with the same hand but different kinematics.

Action chunking. Instead of one action per inference, the policy emits a chunk of the next k (e.g. 50) actions. It reduces inference frequency, smooths motion, and — the surprising part from the ACT paper — reduces compounding error, because the policy commits to a coherent short plan instead of re-deciding (and re-dithering) every 20 ms. Temporal ensembling overlaps successive chunks with exponential weights for smoothness.

5. Imitation learning: the route that actually worked for manipulation

If reward engineering, resets, and safety make RL on a real arm painful, the pragmatic alternative is to show the robot. Behavioral cloning (BC) treats demonstrations as a supervised dataset: regress action from observation, minimizing ‖πθ(o) − a*‖. It is embarrassingly simple and, with enough demos and the right output distribution, it is the backbone of every modern manipulation policy.

Its classic failure is covariate shift: the demonstrator never visited the slightly-off states the learner drifts into, so the learner's error compounds — a small mistake leads to an unfamiliar state, which produces a bigger mistake. Over a horizon T the error grows O(T²) in the worst case, versus O(T) for a policy trained on its own state distribution. DAgger fixes it by rolling out the learner, having the expert label the states it actually visits, and retraining on the union — effective, but it needs an expert on call during training. The modern remedies are architectural: predict chunks (ACT) and predict distributions (diffusion), both of which make the learner far less likely to drift in the first place.

ACT: action chunking with transformers

ACT (2023, the ALOHA paper) feeds images (ResNet features) and joint state into a transformer encoder-decoder that outputs a chunk of k actions at once. Because human demonstrations of the same task vary (multimodal data — two different but valid ways to grasp), a plain L1 regression averages them into a useless middle. ACT wraps the policy in a CVAE: a style variable z, inferred from the demo at training time, is decoded alongside the observations, and set to its prior mean at test time. The result reached 80–90% success on fine bimanual tasks (ziploc bags, battery insertion) from ~50 demos per task on $20k hardware, and is still the first thing to try on a new LeRobot setup.

Diffusion Policy: actions as a denoising process

The cleaner solution to multimodal demonstrations is to stop regressing and start sampling. Diffusion Policy (2023) models the conditional distribution over action chunks p(at:t+k | ot) with a DDPM: training adds Gaussian noise to demonstration action chunks at a random noise level and trains a network εθ(anoisy, o, step) to predict the noise; inference starts from pure noise and runs the learned reverse process for K steps (DDIM reduces K from 100 to ~10 for real-time use). Gradient fields of a denoiser can represent arbitrarily multimodal distributions, which is why diffusion policies handle "left or right around the obstacle" where BC with an MSE head would drive straight into it. The price is inference cost: K forward passes per chunk, which action chunking amortizes.

Animation: a diffusion policy denoising a trajectory

Start: a 24-waypoint action chunk that is pure Gaussian noise. Each step the "denoiser" (here an analytic stand-in that knows the clean demonstration path) removes a scheduled fraction of noise, exactly as εθ would. Fewer DDIM steps means faster inference and a slightly rougher path — the real trade-off on a 50 Hz control loop. The dashed curve is one of two valid demonstrations (left or right around the obstacle); resample noise and the sampler may commit to the other mode — the multimodality that MSE regression cannot express.

Flow matching is the current refinement: instead of a stochastic reverse diffusion, learn a velocity field vθ(at, o, t) that transports noise to data along straight-line paths, and integrate it with a handful of Euler steps. Same expressivity, simpler objective (regress the velocity (a − noise) at interpolated points), fewer inference steps. π0 and its descendants use flow matching in their action experts.

6. Generalist policies and vision-language-action models

ACT and Diffusion Policy are one task, one robot, ~50 demos. The 2022–2026 story is the same one that played out in NLP a few years earlier: pool data across tasks and robots, put a big pretrained backbone in front, and let language be the task specification.

Two lessons across the table. First, action representation moved from discrete tokens to continuous flow/diffusion heads: tokens let you reuse the LM head unchanged (RT-2, OpenVLA) but quantize actions coarsely and decode autoregressively (slow, 1 token per action dim); a dedicated action expert outputs a whole chunk of continuous actions in a few flow steps. Second, the VLM is the pretraining: web-scale vision-language gives the policy semantic generalization ("put the extinct animal in the box") that no amount of robot data provides, and the vision tokenization you learned for VLMs applies unchanged — a VLA is a VLM whose output modality is motion.

Animation: the VLA inference pipeline and its latency budget

Camera frames and the instruction are tokenized (images → a few hundred patch tokens each, see Multimodal), the VLM backbone runs a prefill over them, the action head produces either one discrete token per action dimension (autoregressive, slow) or a continuous chunk in a few flow steps, and the chunk is streamed to the robot at 50 Hz while the next inference starts. The numbers under each stage are a realistic budget on a single consumer-class GPU; the bar at the bottom shows how many control ticks the chunk covers versus how long inference takes — when inference is longer than the chunk, the robot stalls, which is exactly the problem async inference and small VLAs exist to solve.

The latency budget, worked. Suppose a 50 Hz controller (20 ms per tick), two 224×224 cameras (≈ 256 tokens each after a SigLIP-style encoder), a 20-token instruction, and a 3B backbone. Prefill of ~540 tokens on an RTX-class GPU: ~40–60 ms. A flow-matching action expert with 10 integration steps over a 50-action chunk: ~30–50 ms. Total ≈ 100 ms ≈ 5 ticks, while the chunk covers 50 ticks (1 s) — comfortably ahead, so the next chunk is ready long before the current one runs out, and temporal ensembling blends the overlap. Now do the same with OpenVLA-style token actions: 7 action dims × 1 autoregressive decode step each ≈ 7 × 25 ms = 175 ms on top of prefill, for one action — barely 5 Hz without chunking. This is why every 2025+ VLA has a continuous action expert, and why SmolVLA's asynchronous inference (policy server predicts the next chunk while the robot executes the current one) matters on cheap hardware.

7. RL for robots and RL for LLMs: the same math

Having seen PPO twice, make the correspondence explicit. In RLHF/GRPO the state is the prompt plus the tokens generated so far, the action is the next token, the episode is one completion, and the reward arrives once at the end — a horizon-T problem with a single terminal reward, which is why GRPO can get away with no critic (the group mean is a good enough baseline when every trajectory is scored once). Robotics has dense-ish rewards and long horizons, which is why it still wants value functions. But the policy-gradient estimator, the clipping, the KL regularization toward a reference policy — identical (Chapter 11).

Where the reward comes from is the real difference. LLM RL has moved toward verifiable rewards (unit tests, math checkers) precisely because learned reward models get exploited. Robotics has always had this problem in reverse: success is easy to verify in simulation and expensive to verify in the real world (a human or a learned success detector watches the episode), so RL post-training of VLAs — take a π0/OpenVLA-style policy trained by imitation, then run PPO/SAC-style fine-tuning with task success as reward — is the 2025–2026 frontier, mirroring SFT-then-RL for LLMs exactly. Imitation gets you to 70%; RL on the robot's own rollouts gets you to 95%, because it sees and corrects the learner's own failure states (DAgger without the human).

Offline RL asks the complementary question: can we learn a better-than-demonstrator policy from a fixed dataset with rewards, with no further interaction? The obstacle is extrapolation error — Q-learning will happily assign high value to actions never seen in the data. CQL penalizes Q on out-of-distribution actions; IQL avoids querying Q on unseen actions at all by fitting value functions with expectile regression and extracting the policy with advantage-weighted regression. Both matter for robotics because logged data is the asset you actually have.

World models. Dreamer-style agents learn a latent dynamics model from pixels and train the policy entirely inside imagined rollouts — thousands of imagined steps per real one. JEPA-style objectives (predict in representation space rather than pixel space) and video-generation models are the current push to make world models that generalize across robots and scenes; if they work, model-based RL finally gets the sample efficiency robotics needs. The LLM analogy is test-time compute: a world model lets a policy "think ahead" with simulated rollouts the way a reasoning model thinks ahead with tokens.

8. Data: where it comes from and how to use it

Teleoperation produces nearly all manipulation demos. The ALOHA pattern — a cheap leader arm you move by hand, a follower arm that mirrors it, cameras recording both — is what LeRobot's SO-100/SO-101 kits reproduce for a few hundred dollars. Each recorded episode is a sequence of (images, joint state, commanded action) at the control rate; 50 episodes of a task take about an hour. VR controllers, spacemice, and hand-tracking from video are alternatives with worse precision and better scale.

Datasets. Open X-Embodiment pooled 60 datasets from 22 robots (1M+ episodes) and showed cross-embodiment transfer is real. The LeRobot dataset format on the Hugging Face Hub is now the open standard: a Parquet table of per-frame rows (state, action, timestamps, episode index) plus MP4-encoded camera streams, with an info.json describing features and fps and episodes.jsonl indexing episode boundaries. delta_timestamps at load time assembles observation histories and action chunks on the fly, which is how the BC code above got 16 future actions per row. Augmentation (random crops, color jitter) matters more than in vision classification because demos are few and cameras drift.

Do robots have scaling laws? Partially. Success improves log-linearly with demos and with the diversity of objects/scenes, and VLA performance tracks backbone size — but the data is a few orders of magnitude smaller than text, and the "token" (a 20 ms action) carries far less information. The field's bet is that web video and simulation close the gap; that bet is unresolved.

9. Evaluation: the part nobody does well

The headline metric is success rate over N episodes (N = 20–50 in sim, often only 10 on real hardware), with episode length and sometimes a partial-credit score. Simulation benchmarks let you compare fairly: LIBERO (130 language-conditioned manipulation tasks in four suites testing spatial, object, goal, and long-horizon generalization — the standard VLA benchmark), SimplerEnv (simulated replicas of real RT-1/Bridge setups, so sim scores predict real-robot scores), Meta-World (50 tasks for multi-task/meta-RL), and the LeRobot-bundled PushT / ALOHA-sim / xArm environments.

Real-world evaluation protocol, if you ever report one: fix the set of initial configurations in advance (photograph them), randomize the order, run every policy on the same set, report the count out of N rather than a percentage of a tiny N, and record videos. The reproducibility problem is severe — the same checkpoint on a different lab's robot, lighting, or camera mount can lose 30 points — and it is the main reason VLA papers are now expected to report SimplerEnv or LIBERO alongside their real results.
